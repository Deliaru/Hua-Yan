# WP-U2 前端：业务员与研发工作面、Agent 协作栏、签字按钮、觉视图

> 负责：前端 Agent（A 负责合并与联调）｜时段：T+0～16 用接口样例开发，T+16～24 接真实接口｜分支：`dev/u`（从 main 切出，只动 `web/`）
> 依据：`REPLAN-v5.md` 第 3 节（D2、D3、D13、D17～D22），尤其 **3.2 前端硬性要求七条**；视觉方向按 Apple macOS 工作台

## 目标

把界面从「三个人和助手聊天 + 确认卡」改成**「工作面 + Agent 协作」**：人在中间直接操作自己的工作对象，Agent 在右侧旁听、起草、批注，**也接受自然语言指令**（D21）；**按钮就是签字**。觉提出的决策挂在它所说的东西上；觉视图把「流程由觉提出的决策推动」画出来。没有产品经理页面。

界面**不做任何权限判断**（铁律 4）：看到什么、按钮能不能签，都以门面返回为准；门面拒绝时原样显示它给的那句话。

## 依赖

- 接口样例 `web/src/fixtures/*.json`（WP-C 第 0 步，开工即做）：样例到之前只按契约模型搭骨架；T+16 之前**只用样例开发**，不自造数据结构，不写门面替身。
- 真实接口：WP-C 的 `ui/server.py`（T+12～16）。合并与 Agent 协作焦点按契约 v5.2（C14），现成产品由研发审定按 v5.3（C15）。
- 单卡对照数据：B 在 T+8 前交付 `web/src/fixtures/single_card.json`（一次真实运行导出，结构见 `WP-E2-single-card.md` 第 1 步）；接口由 WP-E2 提供，结构与样例相同；T+16 可砍为静态图。
- 「下一句」与检查点载入：WP-I2 提供数据源与接口（检查点 = 现场配置 + 回放录制缓存 + 模拟时钟跑出来的状态，Agent 草稿与现场一致，**不带「离线」标注**），本包只做按钮与接口调用。

## 视觉

沿用 dev/a 已确认的 Apple macOS 工作台方向：中性 `#f5f5f7` 底，磨砂只给工具栏、侧栏、底栏；分组纯白圆角 12，行间左缩进分隔线；Inter + 苹方 / 微软雅黑，字重只用 400 / 600；**蓝只给交互与选中，橙只给「需要决策」，红只给拦截与错误**；不卡片套卡片，不暴露内部 id 与枚举（`rd_accepted` 显示为「研发已接单」），不用红绿状态条。

## 交付物与已定设计

### 0. 外壳
- 工具栏：身份切换（业务员 S01、研发 R01 / R02、主管；来自 `actors`，无登录）、「新开一轮」、状态条（`status()`：模拟数据、种子占位、Jev 实现、觉模型、抽取器、Agent 在线 / 离线、现场 / 回放；降级标黄）。
- 侧栏 source list：工作面（随身份）、觉视图、三层对照、评测（含单卡对照）。**删除 `pages/Pm.tsx` 与所有产品经理入口。**

### 1. 业务员工作面（L1）
| 区域 | 内容 |
|---|---|
| 中间：对话 | 客户发言与业务员发言直接录入（演示者扮客户），不经过 Agent。两个输入框分开：「客户说」与「发给客户」。「下一句」按钮只把下一句客户的话填进「客户说」输入框，由人发出 |
| 「发给客户」 | 预填 `reply_draft`（标「Agent 起草」），可改后发出；门面拦截时在输入框下用红字显示原因（「第 2 句涉及保密内容，请改写」），不发出。旁边两个按钮：「帮我回一句」（发给 Agent 一句固定请求，Agent 把草稿写进 `reply_draft`）、「直接推荐」（`recommend`） |
| 右侧 Agent 协作：觉的决策 | 场景需求卡（每个槽位挂原话，点开看原文）；追问提词（话术 + 概率，点一下填进「发给客户」）；Jev 推荐卡；**推荐还是升级**：橙色卡「建议转产品经理 Agent」+ 可编辑的升级说明 + 按钮「转产品经理 Agent」；回问提示（只出现槽位与话术）；客户评价卡（通过 / 不通过 + 原因） |
| **现成产品建议（D17、D22）** | 业务员不签字。`SessionView.reuse` 为 `pending` 时一行灰字「产品经理 Agent 找到现成产品（产品名），研发审定中」；`adopted` 时显示推荐卡：产品名、用法、面向客户的说明（标「研发 X 审定」）、依据 `basis`（只有归属标签），按钮「填进发给客户」（由业务员发出）；`declined` 时灰字「研发未采用，已转接单」；`none` 时灰字「产品经理 Agent 已查，无现成产品，已转研发」 |
| 解密 | 客户懂化学、要原理时 Agent 提示，按钮「申请解密」；批准后研发审定的说明出现在Agent 协作栏，由业务员转交 |
| 与 Agent 协作（D21） | Agent 协作栏底部常驻输入框，标「与 Agent 协作（不会发给客户）」，历史可折叠；与「发给客户」在视觉上明显分开。例：「客户问 LV205 能不能用在棉上」「把这句说得客气点」「升级说明里补上客户说的回修三次」。Agent 改动就地出现在对应位置（回复草稿、升级说明），带「Agent 起草」标记；Agent 提议的生效动作（如申请解密，`PendingAction`）出现在工作面签字区，显示内容本身，「确认 / 拒绝」调 `agents/approve` / `agents/reject`；对话里没有签字按钮 |

### 2. 研发工作面（L3）
| 区域 | 内容 |
|---|---|
| 左：收件箱 | `questions(viewer)` 分两栏：**准备中**（只显示「产品经理 Agent 正在起草 L2」之类，没有按钮）与**待签**（橙色，有按钮）。每项显示决策名、对象、`scored_by`：规则打分显示「到点」，模型打分显示概率；机会汇聚（D19）显示「2 位客户、同类需求」，展开后并排显示各单的客户原话与产品经理 Agent 的判断理由（`merge_note`），按钮「合并」/「现在不需要」 |
| 中间：需求单 | 以化学语言（L3）为主体，每条右侧并排写来历：针对的场景词 ← 对应的产品需求（L2）← 客户原话；顶部是需求单抬头（要解决什么、已知条件、未能转译的客户信息、方向假设）与「觉在这张单上提出的决策」（取自觉视图接口，显示提出、准备、签字三个时刻，签字区挂在下面）；每条带依据标签（归属人 · 知识 · 被引用次数，L3 原文研发可展开）；`edited_by` 为空的条目标「Agent 起草」；条目可直接改（调 `req-item`）；觉与 Agent 的批注按 `AgentMessage.target` 显示（当前后端挂在整张单上，集中显示在需求单顶部）。产品需求（L2）全文标「产品经理 Agent 起草」，放在右侧「这张单的来历」；客户原话 / L2 / L3 三栏完整并排留在「三层对照」页 |
| 签字区（随当前待签决策变化） | **现成产品审定（D22）**：产品、依据的 L2 案例（原文可展开）、给客户的说明（可直接改，调 `reuse-note`）、泄露自查结果，「通过并转给业务员」/「不采用」（理由输入框）；知识冲突：「更新适用表」；接单 / 退回（理由输入框）；确认转译；沉淀（逐条显示 `contribution_drafts`，每条一个「沉淀为我的知识」）；封存 / 放出两栏（`points_draft`：左「对客户说」、右「封存（只有研发可见）」，`self_check` 命中的句子红色下划线）；发布审定（业务员将看到的说明书与用法 + `leak` 结果）；解密批准 / 拒绝；「录入试样（模拟 ELN）」 |
| 忽略 | 每张待签卡上一个次要按钮「现在不需要」（`resolve(dismiss)`），是目录飞轮「被忽略率」的数据来源；门面不允许时显示原因 |
| 知识与积分 | 侧栏「知识与积分」保留（`ledger`、`contributions`）：本人的知识、被引用次数与积分，以及全员积分榜。演示中研发接单后点开，看到 P01 的历史案例因被引用记分（`cited`）——「谁的知识被用了，谁得分」 |
| 按钮可用性 | 待签才显示按钮；按下后门面拒绝时，在按钮旁显示门面返回的原因（「还有 1 条未答回问」），不在前端自己算 |
| 与 Agent 协作（D21） | 同业务员，`focus` 为当前打开的需求单。例：「给客户的说明别提那家客户的工况」「第 2 条加上不能影响色光」「把我改的第 3 条提炼成可沉淀的知识」「封存栏里去掉 pH 那条，放到对外要点里换个说法」「说明书第 2 句改写一下」。改动就地出现在条目、沉淀草稿、两栏、说明书上；Agent 提议的确认、沉淀等（`PendingAction`）出现在签字区，显示内容本身，人确认即生效 |

### 2′. 主管
身份切到主管时，工作面只有收件箱：拼凑（`leak_risk`）待签卡，显示提问者、证据计数，按钮「冻结权限」/「现在不需要」。

### 3. 觉视图
- 选一条需求线程（首个会话 → 发布）；横轴业务时间，每个决策一条泳道，主题（机会汇聚）单独一条。
- `scored_by` 为 `jue_k` / `onejev` 的点画曲线 + 虚线阈值；`rule` 画阶跃并标「规则 · 到点」，**不标概率**。
- 节点（被提出的问题）显示提出、准备完成、签字三个时刻，以及主人、签字人、处置结果；点开看证据。
- 底部计数：觉判断 `n_judgments` 次、觉的模型调用 `n_llm_calls` 次（取接口值，不写死；含 OneJev，`jue_k` 模式下为 0；状态条显示觉用的是哪种模式）、提出决策 `n_questions` 个、人签字 `n_signatures` 次。
- 以业务员身份打开时只有接口返回的那几条泳道，界面不再过滤。

### 4. 单卡对照（评测页内）
同一张需求卡、同一个模拟客户：左边一次性翻译，右边化言，按轮播放对话，右边同步显示觉的逐轮概率；底部是研发会不会退回，再接 60 张卡三组统计。开发用 `single_card.json`（B 交付），接口就位后换成 WP-E2 接口；两者都标「模拟数据」。

### 5. 三层对照、评测
保留，状态名改为 v5 的说法（「研发已接单」「已复用现成产品」等）。

### 6. 离线
离线与现场是**同一个工作面**（硬性要求 1）：离线时 Agent 草稿处显示「离线，无草稿」或规则骨架产物（带标注），其余操作不变；不做剧本播放器。

## 验收

1. **REPLAN 3.2 前端硬性要求七条**逐条截图对照，违反即返工；REPLAN 3.3、3.4 两张表里的每个按钮都能在界面上找到。
2. 接真实接口（离线配置，接口样例模式已删除）：业务员工作面能看到追问提词、升级卡、现成产品「审定中」与审定后的推荐卡；研发工作面能看到准备中 / 待签两栏、现成产品审定与带来历的需求单（三栏并排在三层对照页）；觉视图画出规则阶跃与 Jue-K 曲线两类。
3. 接真实接口后（T+24 前）：以演示者身份按 REPLAN 3.7 主线从头操作一遍，再走一遍 D17 支线（研发只出现「现成产品审定」一项，审定后业务员拿到说明，研发没有接单）；录屏或截图序列放 `docs/assets/demo/`。
4. `npm --prefix web run build` 通过，无 TypeScript 错误；界面里搜不到 `rd_accepted`、`pm:agent`、`sess:` 之类的内部 id 与枚举。

## 不做

产品经理页面；剧本播放器；确认卡参数 JSON；前端权限判断与可签条件计算；登录；移动端；流式输出；新的后端接口（缺什么提给 A，在 `ui/server.py` 里加）。

遗留给 A / WP-I2：

1. 冻结后业务员侧不可见：会话视图无冻结状态，L1 回答仍说「可以为客户申请解密」。
2. 拼凑风险规则过敏：`n_blocked` 计全部被拦截的 L3 条目（实测一次检索 30 余条），任何人检索 3 次几乎必触发。
3. 现场模式下主管没有 Agent，拼凑风险停在「准备中」，主管工作面不出卡（hub.dispatch 只在 gateway_mock 时替主管准备）。
4. 试样原因恒为 none，知识冲突无法从界面触发。
5. 批注只能挂到需求单级别，挂不到条目。
6. 需求单视图无试样状态（前端由时间线节点推断）。
7. 条件 / 未转译项无独立字段（已定留 WP-I2）。
8. 演示接口：下一步、检查点列表、载入检查点（前端已留入口，接口返回列表时出现）。
9. 业务员看不到自己解密申请的状态（前端只在申请成功后显示一次「已申请解密，等研发审批」）。
10. 需求单摘要无客户，侧栏两张同现象的单看起来一样。
11. `scripts/demo_mainline.py` 仍是 v4 主线，在 v5 下第 3 段「回问」处 IndexError；`/api/offline-mainline` 异常时服务不返回响应。前端不再调用该接口。
