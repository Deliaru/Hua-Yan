## A｜需求直达，不走样

- **一句话**：客户只说现象，化言追问到研发要的信息；现有产品解决不了的，带着客户原话直达研发，每一层每一句都指回原话和知识的主人。
- **现场怎么演**：一位客户的对话 → 场景需求卡（原话）→ 产品经理 Agent 起草 L2、研发接单、L3 → 研发签字 → 结果回到客户。
- **证据**：必问信息完整率 49% → 91%；应升级的卡研发退回比例约 95% → 19.5%；同一批 6 份需求，人工中转节点 30 → 14 → 5，客户自助 2/6（`docs/reports/distortion/`、`docs/reports/v6_routes/`）。
- **现状**：已有。
- **缺口**：主办方终赛数据（业务问答样例、客户需求及方案）到手后，用它重跑一次失真对照。

## B｜研发判断一次，全组织用上，知识仍在研发手里（契）

- **一句话**：研发签一次字，前台从下一位客户起就会用这个判断，但看不到机理；授予可撤销，撤销后行为立即停止。
- **现场怎么演**：四步主演示：第一位客户升级、研发授予一次；第二位同类客户在一线解决；换了工艺条件的客户不被错误推广；撤销后退回研发。
- **证据**：同一批 11 个问题与 V6 对照：正确自助处理 5 vs 1、研发重复参与 2 vs 6、未经授权的确定推荐 0 vs 1（`docs/reports/qi_demo/`）。
- **现状**：已有。
- **缺口**：可选：在公开目录起草的真实型号上再走一遍（种子已起草，跑通过一段对话）。

## C｜该决定的事由觉提出，而且有两件只有学习才做得好

- **一句话**：代码里没有写死的流程；觉看着全过程提出「谁此刻要决定什么」。试样失败预判和判断过时这两件，规则做不好，觉从结果里学。
- **现场怎么演**：时间线上一单从提出 → Agent 准备 → 人签字；一张即将试样的单被觉拦下、先回问客户。
- **证据**：离线轨迹上，`trial_risk` 的 test AUC 为 0.826，规则 0.498；`stale_capability` 为 0.749，规则 0.700（`REPLAN-v8.md` Q9.4 现状）。状态机组与觉组并排的主数字（同等拦截下少打扰研发多少次）还没有。
- **现状**：两个家族已实现；对照主数字未出。
- **证据怎么拿（2026-10-22 人定：乙）**：主数字用离线轨迹对照，模拟月只作界面上的回放、不作证据来源。
  - 轨迹与标签沿用 `scripts/make_jue_k_data.py`、`sim/trajectory.py`、`sim/world.py`（试样成败由世界规律给出）；
  - 状态机组的规则在验证集上从三条候选里选最强的一条，选定后不改，原文写进报告；
  - 主数字：试样失败预判「拦下同样多的失败，觉比状态机少打扰研发几次」；判断过时「比状态机早几次使用发现」；漂移后两组的恢复；
  - 多个种子，报告写进 `docs/reports/foresight/`，同一种子可重放。
- **缺口**：离线对照脚本与报告（`data/tmp_tune.py` 是调世界时的草稿，正式版另写，不沿用其中试过的世界参数变体）；时间线页的回放。

## D｜进得去企业：接现有资料，不换入口

- **一句话**：企业现有的资料原样接入，产品目录从公开资料起草、人审定后启动；员工在钉钉的待办卡片上签字，不换入口。
- **现场怎么演**：官网公开目录（177 条）起草种子 → 跑通一段客户对话；终赛数据接入的步骤演练一遍。
- **证据**：目录起草引文全部核对通过；编译出 61 条候选结论，69 条挂为第 0 天能力的依据（VISION 1.2 主张 7）。
- **现状**：目录与适配器已有；钉钉未做；企业真实 RAG 适配器要等现场对接。
- **缺口**：钉钉做不做（见待人定 3）；终赛数据接入流程需要提前演练。

## 不当主打，被问到时能答

- **机密守护**：权限在数据层，由测试守住（`test_wp_a1`、`test_wp_l`）；行为发现只看业务员的实际行为（`leak_risk`，Q9.8 结构部分）。不做泄密剧本对照。
- **自进化**：照实讲，重训没有让觉更快问全，效应小（`docs/reports/jue_evolution/`）。
- **VISION 1.3 十二个升级点**：对外只讲和 A–D 对应的几条，其余收进第 10 节的评委追问。
