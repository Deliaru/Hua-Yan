# 决赛范围｜把真实试用的价值讲清楚

> 更新：2026-10-22。决赛：2026-11-08。**现行实施顺序、范围和完成条件统一见 [REPLAN-v9](REPLAN-v9.md)**；本文只维护价值、可观察证据和展示方式，不再另排开发计划。
>
> V9 的交付目标是四类真实岗位在同一个共享试用实例内，在项目方协助下完成全链条业务试用。下文区分已有机制、历史证据和本次待验证目标，不表示真实试用已经发生。

## 1. 一件业务，四种价值

化言要让专业问题进入组织后，得到恰当的澄清和判断；判断经过确认与授予，成为下一次业务可以使用的能力。觉负责持续形成、维持、筛选和提交值得决定的事项，契负责专业判断的来源、适用范围、使用授权与生命周期。两者共同服务业务员、真人产品经理、研发和研发负责人。

L0–L3 是知识边界；四种岗位不是每张单必经的四道审批。负责人能在授权范围内看清工作、例外和责任，不因其职位而自动获取全部原文。

| 价值 | 真实试用中应发生的变化 | 已有基础 | 本次还要拿到的证据 |
|---|---|---|---|
| **A 需求直达且可纠正** | 客户原话成为可判断的需求；未知、补充和更正有正常路径；无需每个岗位重复转述 | 原话证据、结构化需求、按性质分流和模拟失真／路线对照 | 新输入与多人交接真正完成；系统漏解、误解和人工修正如实记录；不能将模拟节点数直接换成实际省时 |
| **B 一次判断影响下一次业务** | 研发确认一个有条件的判断，经适当授予被后续需求使用；边界不符时保留专业处理，撤销后停止使用 | 契、能力状态、来源指纹、归属及脚本对照已有实现 | 由真实责任人确认和授予；完整限制未丢失；下一单的实际处理改变；检查本次业务涉及的撤销与来源刷新结果 |
| **C 系统持续关注值得判断的事** | 无需人逐项下令就提出有依据的事项；状态变化后继续维护；人能接受、修改、拒绝，其他工作仍可进行 | 决策目录、规则／学习评分、问题总线和 Agent 准备机制 | 事项提出、处理、更新或结束的真实过程，以及漏报、重复与无用打扰。学习增益另做针对性比较 |
| **D 能交给企业岗位试用** | 四类岗位共享同一业务，各做自己的工作；页面返回保留已提交结果，普通失败可以提示后重跑 | 多角色演示、资料适配器、公开目录与部分状态持久化 | 一个共享实例、简单角色会话、基本保存、可用材料和真人反馈；正式企业接口按实际完成状态标明 |

当前按浏览器隔离的 Demo 适合独立体验，不构成 D 的证据。真人产品经理与后台 `pm:agent` 各司其职；负责人能从管理视图回查具体业务，提出与实际工作有关的意见。

## 2. 证据怎样对应主张

| 主张 | 可以使用的证据 | 尚不能据此声称 |
|---|---|---|
| 协作路径可以减少中转 | [V6 路线对照](../reports/v6_routes/README.md) 的路径和计数解释 | 真实企业减少了同等比例的工时；这是觉学习模型的单独贡献 |
| 条件化授予改变后续行为 | [契示例](../reports/qi_demo/demo.md) 与 [对照](../reports/qi_demo/compare.md) | 已完成真人共同工作；该曲线是模型学习曲线；所有专业条件均已验证 |
| 抽取修复有进展 | [理解只在一处](../reports/understand_once/README.md) 的回归核对 | 45 句是独立准确率或新输入已无问题 |
| 学习机制能够训练与重训 | [Jue-K](../reports/jue_k/README.md) 与 [自进化](../reports/jue_evolution/README.md) 的对应报告 | 每个家族都有学习增益，或已在真实企业持续减少返工 |
| 可交付全链条试用 | 开发者走通主要业务，修复已知阻断，资料和角色入口可用 | 真实岗位已经参加、认可或长期采用 |
| 一次真实试用完成 | 真人处理业务、下一次使用，以及必要帮助和实际反馈的记录 | 已正式上线、普遍有效、长期 ROI 成立 |

引用数字时说明来自哪次运行、样本和计算口径，区分模拟与实际。当前不再用一条“C 主数字”代表全部价值，也不预设“只有学习才能做好”后再挑数据证明。模型增益不成立的结果照样报告，不取消觉主动组织判断的产品目标。

## 3. 将组织价值变成可见的变化

展示围绕同一条业务保持上下文：客户问题与已知条件、当前专业判断、已可复用的能力。让观众看到一次确认怎样改变下一次处理，而不是只看到角色标签和 Agent 对话。

| 展示段落 | 屏幕里的真实变化 | 对应价值 |
|---|---|---|
| 需求进入 | 原话、已知／未知、纠正及责任人可见 | A：需求能被理解，也能被纠正 |
| 有关事项出现 | 觉提出事项，显示对象与依据；Agent 实际准备；真人确认或驳回 | C：系统持续关注，人负责判断 |
| 成果成为可用能力 | 展示来源、适用范围和使用授予；下一件条件符合的业务实际复用 | B：一次专业判断进入组织能力 |
| 边界与组织变化 | 条件不符仍需专业处理；撤销后停止使用；负责人看到依据、使用和剩余例外 | B、D：自动化有清楚边界，组织工作可核查 |

三分钟讲述可以使用获准的真实试用录制与可核对回放；需标明过程压缩，不能让观众误以为现场完成了耗时物理实验。现场交互展示一个条件变化或撤销后的后果。具体时长以赛事实际规则调整，不影响 V9 真实试用验收。

让非项目成员看完后复述“谁的工作发生了什么变化、为什么能复用、边界改变后怎么办”。如果只能复述“四层、很多 Agent、积分”，就继续改呈现。漂亮界面服务真实结果；共享业务和真实使用结果在画面中直接呈现。

## 4. 试用结果决定最终口径

进入决赛前，按照 V9 结果分别填写：已经验证的行为、仍未通过的行为、实际参与者反馈、没有观察到的长期效果。公开材料只使用获准内容，内部案例与对手推演不放进公开仓库。

成熟产品已经具备知识治理、人审、持久执行与权限机制。化言的竞争主张应落在这套组合在真实业务中带来的变化，以及觉与契如何共同发挥作用；不使用“别人做不到”“只有我们有”“因为用了工作流就没有创新”等未经验证的判断。

新增功能是否纳入，由 V9 的真实业务需要和验收决定。开发速度不作为缩减必要能力的理由；与当前试用无关的扩展可以保留在愿景中，不抢占现行计划的解释权。
