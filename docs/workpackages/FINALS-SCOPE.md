# 决赛范围｜把真实试用的价值讲清楚

> 更新：2026-10-22。决赛：2026-11-08。**实施顺序、范围和完成条件见 [REPLAN-v9](REPLAN-v9.md)**；本文讲价值、证据和展示方式。
>
> V9 的交付目标：四类真实岗位在同一个共享试用实例内，在项目方陪同下跑完全链条业务。下文每一项都写明已经拿到的证据和本次要拿的证据。

## 1. 一件业务，四种价值

化言让专业问题进入组织后得到恰当的澄清和判断；判断经过确认与授予，成为下一次业务直接可用的能力。觉持续形成、维持、筛选和提交值得决定的事项，契管住专业判断的来源、适用范围、使用授权与生命周期。两者一起服务业务员、真人产品经理、研发和研发负责人。

L0–L3 是知识边界，四种岗位按需求性质参与。负责人在授权范围内看清工作、例外和责任，原文按归属授予。

| 价值 | 真实试用中发生的变化 | 已有基础 | 本次拿到的证据 |
|---|---|---|---|
| **A 需求直达且可纠正** | 客户原话直接成为可判断的需求；未知、补充和更正都有顺畅的路径；各岗位不再重复转述 | 原话证据、结构化需求、按性质分流，模拟失真与路线对照（研发退回约 95% → 19.5%，人工中转节点 30 → 5） | 新输入与多人交接实际完成；系统的理解、人工修正逐条记录；试用里的真实耗时 |
| **B 一次判断影响下一次业务** | 研发确认一个有条件的判断，经授予被后续需求直接用上；条件不同交回研发，撤销即停用 | 契、能力状态、来源指纹、归属及脚本对照（同批 14 题：自助处理 4 → 8，研发重复参与 6 → 2） | 真实责任人确认和授予；限制条件完整保留；下一单的处理实际改变；撤销与来源刷新的效果 |
| **C 系统持续关注值得判断的事** | 系统主动提出有依据的事项，状态变化后持续跟进；人随时接受、修改或驳回，其他工作照常进行 | 决策目录、规则与学习评分、问题总线和 Agent 准备机制（模拟业务周觉提出 56 个问题、人签 22 次） | 事项从提出、处理到更新或结案的真实过程，以及有用、多余与遗漏的逐项记录 |
| **D 交给企业岗位真实使用** | 四类岗位共享同一业务，各做各的事；页面返回即见已提交结果，失败提示后一键重跑 | 多角色演示、资料适配器、177 条公开目录接入与状态持久化 | 一个共享实例、角色会话、基本保存、可用资料和真人反馈；企业接口接通一项展示一项 |

真人产品经理与后台 `pm:agent` 各司其职；负责人从管理视图回查具体业务，针对实际工作给出意见。

## 2. 证据怎样支撑主张

| 主张 | 证据 | 讲法 |
|---|---|---|
| 协作路径大幅减少中转 | [V6 路线对照](../reports/v6_routes/README.md) | 「同一批需求，人工中转节点 30 → 5，进研发的单 6 → 2」；实际工时由试用测出 |
| 授予直接改变后续行为 | [契示例](../reports/qi_demo/demo.md) 与 [对照](../reports/qi_demo/compare.md) | 「授予、撤销立即改变行为，状态跨重启保留」；曲线来自授予机制 |

| 觉能在运行中训练与重训 | [Jue-K](../reports/jue_k/README.md) 与 [自进化](../reports/jue_evolution/README.md) | 「四个发现格训练模型胜过规则；运行中自动重训、换上新模型」 |

| 完成一次真实试用 | 真人处理业务、下一单复用、帮助与反馈的完整记录 | 「真实岗位用化言办完了一件业务，一次判断被下一单用上」 |

引用数字时带上运行、样本和计算口径，模拟与实际分开写。每种价值配它自己的证据；模型增益的对照结果照常公开，觉主动组织判断这一产品目标始终是主线。

## 3. 让组织价值在屏幕上看得见

展示围绕同一条业务保持上下文：客户问题与已知条件、当前专业判断、已可复用的能力。让观众亲眼看到一次确认怎样改变下一次处理。

| 展示段落 | 屏幕里的真实变化 | 对应价值 |
|---|---|---|
| 需求进入 | 原话、已知／未知、纠正及责任人可见 | A：需求被理解，也能被纠正 |
| 有关事项出现 | 觉提出事项，显示对象与依据；Agent 实际准备；真人确认或驳回 | C：系统持续关注，人负责判断 |
| 成果成为可用能力 | 展示来源、适用范围和使用授予；下一件条件符合的业务实际复用 | B：一次专业判断进入组织能力 |
| 边界与组织变化 | 条件变了交回研发；撤销后立即停用；负责人看到依据、使用和剩余例外 | B、D：自动化边界清楚，组织工作可核查 |

三分钟讲述使用获准的真实试用录制与可核对回放，标明哪里做了时间压缩，物理实验用已有结果；现场交互展示一个条件变化或撤销后的后果。时长按赛事现场规则调整。

检验标准：非项目成员看完能复述「谁的工作发生了什么变化、为什么能复用、条件变了怎么办」。复述停留在「四层、很多 Agent、积分」时，继续打磨呈现。界面为真实结果服务，共享业务和真实使用结果直接呈现在画面上。

## 4. 试用结果定最终口径

进入决赛前，按 V9 结果填写：已经验证的行为、试用中暴露并修复的问题、参与者反馈、上线后继续观察的长期效果。公开材料使用获准内容，内部案例与对手推演留在仓库之外。

知识治理、人审、持久执行与权限各有成熟产品。化言的竞争力在于这套组合在真实业务中带来的变化：觉主动把值得判断的事提出来，契让判断一次、复用多次、随时可收回。我们用试用里看得见的变化说话。

新增功能是否纳入，由 V9 的真实业务需要和验收决定；与当前试用无关的扩展保留在愿景中。
