# 决赛范围｜以创新主张组织讲述与后续工作

> 2026-10-23 重整。当前代码基线为 `review/v8-closeout-v9@94d5a88`。本文件说明展示重点与工作取舍；具体执行记录仍在 [REPLAN-v9](REPLAN-v9.md)，事实核对见 [STATUS](../STATUS.md)。

## 1. 已明确的目标

用户要求按创新大赛式路演组织材料：痛点、创新、价值和长期方向居于主线，觉的完整思想必须展开；现场形式是 PPT、讲述与答辩。软件与试用提供支撑主张的材料，整场讲述应能独立成立。[讨论依据](../DISCUSSION-RECORD.md)

**核心主张：让专业判断成为组织能力，让研发创新重获时间。**

觉从持续信息中发现值得处理的事项，契让专业工作形成后续可用的能力，Agent 承接材料与执行，人投入真正需要其专业判断的部分。企业每处理一类问题，就有机会增加下一次可以使用的能力。这条主线连接具体业务、岗位变化与长期创新。

产品愿景是企业决策神经系统，技术愿景是通用信息反射。完整愿景在 [VISION](../VISION.md) 中展开，PPT 与答辩内容在 [PITCH](../PITCH.md) 中维护。

## 2. 展示需要建立的三项认识

| 主张 | 主讲应让人理解什么 | 需要的支撑 |
|---|---|---|
| 觉具有独立的技术问题意识 | 信息怎样形成事项，未决问题怎样维持，哪些值得投入注意，经验怎样改变关注 | 现有发现与总线机制；标明场景的学习实验；后续真实处置反馈 |
| 契让专业投入持续发挥作用 | 第一次判断怎样改变第二、第三次业务；哪些能力可以被谁在什么条件下使用 | 同一业务的专业判断、授予、后续复用；产品经理与研发贡献同时出现 |
| 协作改变能够释放专业精力 | 销售、产品经理、研发各自减少哪些重复工作，又承担什么专业责任 | 同一类需求的处理过程、人员实际参与、真实岗位反馈 |

语义编译支撑需求质量，知识分层与来源支撑专业能力使用，实际结果支撑后续改进。素材各自服务以上主张，避免把每一项功能都抬成一项并列核心创新。

## 3. 当前版本处于什么位置

V9.1–V9.6 已有共享实例、角色绑定、模型等待期间的协作、按对象组织助手、准备与失败重试、专业限制以及开发者四角色走链等记录。V9.7 真人试用、V9.8 展示回填尚无完成记录。

上一轮 review 和 V9.6 记录暴露了几组直接影响业务承诺的问题。这次整理保留这些问题及其来源，形成下一轮工作的建议顺序；修复实现由执行方结合当前代码判断。本文不会把已发现的缺口写成已经完成的能力。

### 3.1 先把现有核心承诺做完整

| 工作主题 | 要达到的业务结果 | 为什么与核心主张直接相关 |
|---|---|---|
| 条件修正贯穿处理与发布 | 客户最新条件进入需要重做或重确认的材料；发布使用本轮最终认可的试样与条件；结果回到原业务 | 需求直达的价值取决于原意和修正能否真的传到底 |
| 能力使用遵守当前依据 | 正常推荐、研发直接推荐和撤销后重新匹配，都正确处理有效性、适用情境与专业限制 | 专业判断能够持续复用，要建立在当下仍然成立的依据上 |
| 共享角色入口完整 | 会话写入和助手轨迹读取都使用已有主体与对象归属检查 | 专业能力跨岗位流动时，角色边界在实际入口也要成立 |
| 试用信号与资料可靠 | 已知必需但从未取得的条件能够提示；已确认的冻结建议误报得到处理；产品未确认范围与不受限制区分 | 觉需要帮助人少遗漏、少被无效事项打扰 |

这些主题来自当前已知问题。有关具体分支和证据，查 [STATUS](../STATUS.md)；本次整理不新建通用故障恢复、全量依赖传播或额外审批体系。

泄露风险规则已经出现正常检索误报。沿用上一轮 review 的建议，应先处理这一已知误报，再交给真实岗位使用；可暂时停用这条自动提出的冻结建议，或修正其实际信号。已有访问权限、授予和撤销继续承担相应边界。具体实现需要执行方确认，不能把错误信号交给主管长期反复否决。

对专业知识的变化，要分清使用授权撤销与专业结论撤回。修正各消费路径的遗漏，并不自动要求所有关联知识一起撤回。

### 3.2 让真实岗位完成一件有意义的业务

继续原定 V9.7：由业务员、真人产品经理、研发与研发负责人在同一业务空间参与，项目方可以现场指导、补资料和帮助重跑。客户作为外部需求来源，其材料身份与参与方式单独记录。

试用应产生一份能讲清来龙去脉的案例：客户原本要解决什么，系统补清了什么，哪些事项需要谁判断，产品经理与研发分别留下了什么专业成果，后续业务实际用上了什么。遇到条件改变或问题退回，保留真实处理过程。

参与者的反馈应能回答：哪些事情比原来省力，哪些仍要反复补充，什么地方让人不信任或看不懂，下一次相似业务是否减少了重复参与。岗位工作变化是主要产出，页面点击次数只是过程信息。

### 3.3 为觉补到有业务含义的证据

当前试用模型只加载机会汇聚与判断过时两个学习格，当次开发者走链没有触发它们。因此“整个流程走通”与“学习式觉提供了增益”需要分别回答。

后续可选一个有价值的事项家族，使用含义稳定的特征和独立的处置反馈，观察规则与学习在遗漏、误报、重复提醒或关注时机上的差别。样本来自真实工作还是构造情境，记录清楚；训练与比较使用的数据关系也要明确。投入围绕一道关键答辩题展开，不要求在真人试用开始前把所有家族重训一遍。

### 3.4 将成果写回 PPT 与答辩

把试用中最能解释主张的轨迹、截图、参与者反馈和可核对数字写回 [PITCH](../PITCH.md) 与 [STATUS](../STATUS.md)。主讲围绕创新、企业价值与未来；备答提供机制与实验依据。

现场软件录制可以帮助准备截图和回忆过程，PPT 中用静态前后状态、简洁动画和讲述也能完整表达。现场打开软件不构成主讲成立的前提。

## 4. 尚未决定的扩展

| 讨论过的方向 | 当前地位 | 值得继续投入的条件 |
|---|---|---|
| 多客户需求汇聚并形成共同研发工作 | 现有基础上的进一步候选 | 能更清楚地说明产品经理的商业判断、需求差异及研发目标，而非简单合单 |
| 新成果主动重新服务相关历史需求 | 候选扩展；原业务完成后的结果回流属于当前闭环 | 证明一项专业成果怎样带来多个具体业务变化，并保留各客户适用条件 |
| 业务全景视图 | 可视化候选 | 对实际办事或论证确有贡献；主讲需要的关系图可以直接在 PPT 中表达 |
| 更开放的事项发现、跨领域迁移 | 觉的研究路线 | 有明确研究问题、适配对象与评价方式，能够逐步建立证据 |
| 另起更大的经营管理平台 | 不在当前范围 | 当前围绕需求、专业工作与能力积累发展 |

原回复前半段曾把前几项列为优先开发，后半段在用户纠正现场形式后已将其降回候选。当前没有据此确定 V10 功能包。开发效率可以支持快速试验，新增工作仍要说明它增强了哪项主张或解决了哪项实际问题。

## 5. 工作完成如何判断

文档完成的标志，是读者可以分清项目主张、机制、当前状态、证据与下一步；能够沿着同一套术语准备 PPT 和答辩；执行者能找到现有业务缺口，而无需从多个历史主张体系中重新猜测方向。

近期产品工作的完成标准沿用真实业务需要：核心条件正确流转，能力在有效范围内使用，角色能够共同办完事，关键问题得到有依据的修正。验证围绕已发现的分支与实际业务展开，具体代码组织和修复方式交由执行方决定。

决赛材料应完整表达长期雄心，同时让每个已完成的事实都能找到对应版本和来源。历史模拟、开发者走链、真人试用和未来目标在材料中各就其位。核心价值不需要靠扩大功能清单来维持。
