# 决赛策略与范围｜让需求直达，让创新回归

> 更新：2026-11-01；决赛：2026-11-08。本文组织 PPT 讲述与答辩，呈现化言的创新、价值与发展空间。当前实施计划见 [REPLAN-v10](REPLAN-v10.md)，V9作为历史基础，长期架构见 [VISION](../VISION.md)。当前可展示证据与未完成边界见 [V10阶段证据](../reports/v10-evidence.md)。
>
> V10的交付目标是一份真实报告经专业确认与授予，让下一单直接复用，并由四类真实岗位在共享实例中实际办理。当前软件演练、真实资料读取与真人业务分别记录；试用为决赛提供关键证据，路演同时讲清这条链路为何值得改变，以及觉与契的发展方向。

## 1. 决赛的中心主张

**让客户需求直达专业能力，让研发创新重获时间。**

化言面向工业企业里长期存在的一种消耗：客户不断提出问题，销售反复追问，产品经理反复转述，研发反复解释与返工。每个人都很忙，真正用于客户经营、产品规划和长期研发的时间却越来越少。

化言探索的是企业决策神经系统：**觉从持续变化的信息中发现值得处理的问题，契让专业判断成为可以持续服务业务的能力，Agent 承接材料准备与执行，人回到真正需要其专业价值的位置。**“任务从觉来，能力从契来”概括系统自主工作的来源；人也可以随时提出需求、委托任务和作出判断。

路演要让评委记住三个判断：化言抓住的是企业创新能力被日常协作消耗的痛点；觉与契给出了有辨识度的技术和机制回答；一条需求链路的改变，可以进一步释放整个组织的专业能力。贯穿全场的短句是：**问对的人，只问一次。让专业判断成为组织能力，让创新重新获得时间。**

## 2. 从真实痛点讲到组织价值

研发反馈给出的因果链非常具体：需求不清，导致反复转述和交叉对接；开发目标发生偏差，导致结果不达标、返工；大量短平快项目继续消耗研发，中长期探索被挤压。把这条因果链放进 PPT，评委才能理解少一次传话与公司的未来有什么关系。

化言从客户需求切入，持续保留原始意图、关键条件和后续修正，让材料准备自动推进，已有能力先服务业务，只有真正需要专业判断的新问题进入相应岗位。岗位职责随之发生改变：

| 岗位 | 化言承接的反复消耗 | 人重新投入的核心工作 |
|---|---|---|
| 客户与销售 | 产品信息收集、重复问答、专业信息来回转述 | 客户确认真实需要，销售经营客户、推进商务与成交 |
| 真人产品经理 | 重复整理需求、追问条件、逐单搬运技术结论 | 判断需求价值与产品范围，管理产品生命周期，沉淀需求转化知识 |
| 研发 | 重复解释已有结论、补齐零散材料、处理需求失真引起的返工 | 解决真正的新问题，形成专业成果，开展中长期产品探索 |
| 研发负责人 | 反复询问进度、跨群拼接事实 | 发现共性需求与阻碍，判断工作优先级，为长期研发保留精力 |

其中产品经理的贡献同样进入组织积累：客户表达如何转为产品要求，哪些条件影响选型，哪些需求值得进入产品规划，都应留下可供后续业务使用的判断。客户、销售、产品经理和研发围绕同一需求协作，参与路径由问题决定。

由此可以讲出三层价值。业务层是需求更快走到正确的人与能力，减少传达失真和重复判断；组织层是岗位回归本位，专业成果持续服务更多业务；战略层是让企业在处理眼前订单的同时，保有投入下一代产品的能力。后两层正是化言值得从一次试用继续发展的原因。

## 3. 三项创新，共同回答“为什么是化言”

### 觉：让智能系统主动发现值得解决的问题

大模型擅长回应已经明确提出的问题，企业现场却还有大量尚未被说出来的事项：多个客户反复出现相似诉求，需求条件发生变化，判断所需的信息逐渐齐备，某项任务长期没有进展。**觉研究的是信息到来之后，什么值得进入系统和人的注意。**

我们将这个方向称为“通用信息反射”：面向持续变化的环境，形成、维持、筛选并提交值得处理的事项，再结合行动结果调整后续关注。它既可以具备预设的基础反应，也可以通过训练形成更专业的反应。人在同一场景中会因经验不同而迅速注意到不同线索，这为觉提供了直观的解释；工程上要建立的是能够训练、比较和改进的独立能力层。

化言提供了这个思想的第一个业务落点。觉持续关注需求、专业能力和任务状态，Agent 为发现的问题准备材料，专业人员作出必要判断，结果重新进入系统。值得研究的核心随之清楚：智能体如何获得自己的任务来源，如何持续跟进尚未解决的问题，如何把有限注意力交给真正重要的事项。

### 契：让一次专业判断，服务后续更多业务

一个研发结论通常带着条件：适用什么材料、工艺与范围，哪些情况需要重新判断。化言用契把判断的来源、责任、条件和使用授权连接起来，让后续业务能够调用经过确认的专业能力。

**专业知识的价值因此可以跨岗位流动，专业责任仍然有明确归属。**销售能够获得被授权的解决问题能力；产品经理对需求的转化和范围判断可以复用；研发无需为同一类已确认的问题反复重新解释。企业每完成一件业务，就有机会增加下一件业务可直接使用的能力。

这项创新的展示重点是“下一件业务发生了什么变化”：谁已经不必再次参与，哪些工作直接完成，新的条件又带来什么专业问题。来源、授予、更新与撤销共同支撑这条能力积累路径，具体操作适合在答辩时展开。

### 协作方式：让需求驱动岗位参与

觉回答“什么值得做”，契提供“可以调用什么能力”，Agent 承接准备与执行，人承担关键专业判断。这使客户需求能够直接进入合适的处理路径，减少固定链条里的逐级搬运。

需求的语义编译把客户表达转为保留原意和条件的专业材料，结果回流把实际处理与后续复用连接起来，为这套协作方式提供落地支撑。化言的创新由此同时发生在技术架构、专业能力组织方式和实际岗位协作中。全链条跑通后，销售、产品经理与研发可以从反复对接中抽身。系统积累的也包括问题是怎样被理解、判断和解决的经验，后续相似业务因此能够得到更完整的支持。

## 4. 建议 PPT 主线：先立主张，再让证据兑现

以下约十页是叙事顺序，可按赛事公布的实际时长合并。每页保留一个清晰结论，技术细节与完整实验表进入备答。

| 页 | 核心结论 | 建议画面与讲述 |
|---|---|---|
| 1　让需求直达，让创新回归 | 化言要释放企业被日常协作占用的创新能力 | 一句话定位与客户、产品、研发的共同目标；开场即提出价值 |
| 2　为什么研发总在忙，却难以做长远的事 | 需求失真和重复判断持续挤压长期研发 | 一条需求反复转述、返工的因果图，配研发访谈原意 |
| 3　我们提出怎样的改变 | 觉发现事项，契开放能力，Agent 承接工作，人贡献专业判断 | 一张总体架构图，直接对应业务问题与岗位变化 |
| 4　觉：任务可以从信息中主动长出来 | 信息反射是智能系统持续主动工作的基础能力 | 信息变化→事项形成→材料准备→专业判断→结果反馈，讲清原创问题意识 |
| 5　契：一次判断成为持续可用的能力 | 专业成果能够跨岗位、跨后续业务发挥作用 | 第一次研发判断与下一次直接复用的对照；突出变化与积累 |
| 6　客户需求如何直达专业能力 | 各岗位回到其最有价值的工作 | 围绕同一业务展示协作前后；产品经理的判断和知识沉淀明确入画 |
| 7　这套机制已经带来什么变化 | 机制运行、模拟对照与真人试用分别提供证据 | 精选两三项有解释力的结果，加一段同一业务的演示或回放 |
| 8　它怎样进入企业、持续创造价值 | 现有产品知识与专业工作可以成为起点 | 展示资料接入、岗位使用和能力积累，连到需求响应、研发精力与产品机会 |
| 9　从企业需求直达，走向通用信息反射 | 化言有清楚的业务起点，也有可持续探索的技术方向 | 企业扩展、跨场景 Agent、机器人与具身智能研究三个方向，讲清可迁移的思想 |
| 10　为什么值得继续投入 | 眼前办成一件事，长期沉淀一种能力 | 回到岗位价值与长期研发；明确下一步试点、共同验证与发展诉求 |

演示帮助评委相信主张。选一组有联系的客户需求：已有能力解决其中一部分，觉发现需要专业关注的新事项，产品经理与研发各自作出判断，成果随后服务新的需求。屏幕持续显示需求如何前进、哪些重复工作已经被系统承接、哪些专业工作仍在创造新价值。这样可以把分散在聊天记录里的组织变化，集中呈现为一个看得见的过程。

现场高潮放在“新的需求直接用上了此前形成的能力”和“人终于能把时间交给真正的新问题”。权限细节、撤销操作、失败重试与模型配置放到备答。已有录制、回放与当前界面都可支撑讲述；这份叙事不自动转成一批新增页面或开发任务。

## 5. 大胆展开长期愿景

**化言的长期方向，是让组织拥有持续发现问题、调用专业能力、从结果中积累经验的主动智能。**需求直达是这一愿景的起点，也是最贴近业务、最适合开始验证的入口。

在企业内部，专业判断的积累可以连接更多产品、客户和研发任务。反复出现的客户问题，可以帮助产品经理识别值得产品化的共性需求；跨项目的专业成果，可以支撑研发复用经验、减少重复探索；负责人可以看见哪些工作消耗了关键资源、哪些机会值得长期投入。企业逐渐获得从业务中发现方向、从实践中积累能力的循环。

在技术上，觉可以沿“通用信息反射”继续发展。软件 Agent 面对不断变化的信息，需要主动产生和更新任务；机器人与具身智能面对持续环境输入，需要及时发现变化、危险与行动机会；面向 AGI 的研究，也需要讨论任务如何产生、注意如何分配、经验如何改变反应。觉提供了一个可以独立研究和检验的切入点，契则提供专业能力如何获得、共享和承担责任的组织视角。

这里可以公开提出雄心：**从帮助企业回应客户需求，走向让智能系统持续理解环境中哪些问题值得被解决。**后续研究围绕跨任务迁移、经验训练、持续反馈和环境交互展开。化言既有行业应用价值，也有把应用中提出的问题发展为通用能力研究的空间。

长期愿景在正文中正面讲清，并以“发展方向”“研究目标”标注阶段。它可以大于当前版本；评委应看见团队为何选择这个起点，以及每进一步为什么能够积累新的价值。

试用所得最有价值的材料，是一件业务怎样完成、某位参与者少做了什么重复工作、产品经理和研发的判断如何被下一件业务使用，以及参与者真实提出的修改意见。这些证据让创新主张具体可感，也帮助团队决定下一步发展。

对经济价值，可以给出测算路径：重复处理量与单次专业耗时决定可释放工时，需求准确性影响后续沟通与返工，专业能力复用影响业务响应。展示预测时写明假设与目标；长期研发产出、营收增长和行业影响由后续经营数据持续验证。模拟对照、真实试用、未来目标各用自己的名称，保持数字与来源对应。

对“已有知识库和 Agent 平台为什么还需要化言”的答辩，讲清复用成熟基础设施后的核心贡献：觉研究任务从何而来，契组织专业判断如何持续成为能力，需求直达把两者转成岗位协作的变化。对“通用性在哪里”，说明信息反射的研究问题与可迁移机制，并展示当前场景已做到哪一步。创新来自问题定义、架构与应用机制的共同设计，其说服力由可展示的结果和持续发展的路径建立。

决赛结束时，希望评委能够复述：**化言从需求沟通这个真实痛点出发，用觉与契让专业能力主动进入业务，让岗位回归价值，并为企业的长期创新释放空间。**
