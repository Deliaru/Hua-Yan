## 0. 为什么有 v9

人的感受是「一直在原地踏步」。查下来这个感受是对的：

- `2bab736` 之后两天没有新提交，43 个文件的改动堆在工作区；
- 业务月录制停了两次。第一次世界设定不对，第二次泄露判断冻错人；
- 泄露判断的口径改了三版（被拦命中 → 原理请求 → 行为计数），一次真实运行都还没验证过；
- C 的主数字（同等拦截下少打扰研发多少次）至今没有；
- 四件事里 D（钉钉、终赛数据接入）没有动；
- 决赛日期和形式仍然不知道。

v9 不加新功能。它做四件事：

1. 把这一轮遇到的问题全部记下；
2. 找出反复出现的问题的共同原因，定下今后的做法；
3. 写清楚现在哪些东西能用、哪些数字还有效；
4. 把剩下的工作排成决赛前能交付的几个小包。

## 2. 反复出现的问题与原因

上面 43 条里，下面五种模式各出现了三次以上。每种列出几个实例，再说原因和今后的做法。

### 2.1 在发现问题的地方打补丁，而不是回到负责的那一处

- **实例**：
  - 漏判就加关键词（#1、#2）；
  - 接单出问题就在门面加门（#8）；
  - 失真关不掉就数标签（#10）；
  - 泄露误报就换一个计数口径（#11，改了三版）。
- **原因**：每次都从「这次哪里错了」出发，没有先问「这件事该由哪个组件负责、它有没有手段和信息」。补丁短期内能让这一次运行通过，但会把判断分散到多处，下一次运行在别处又错。
- **今后**：
  - 修任何问题之前，先按 `component-roles-check` 写一句「这件事归谁」；
  - 语义只来自抽取或觉的打分（`no-regex-for-semantics`）；
  - 门面只拒绝权限、做不到、红线三类（`no-judgment-gates-in-facade`）；
  - 同一个口径改到第二版还要改的时候停下来，回到「量的是什么真实产出」重新定。

### 2.2 用几小时的模拟来发现几秒钟就能查出的问题

- **实例**：
  - 「我不是要你们配方」误判、pH 误判、冻错对象、研发被压垮、送样失败 46%：都是在模拟运行跑了几十分钟到几天之后才看到；
  - 修完要重跑才知道修没修好；
  - 接口一过载，录制就中断。
- **原因**：没有分钟级的检查。抽取对不对，可以拿 40 句原话几分钟查完；世界合不合理，可以离线抽 2 万张卡几秒查完；冻结的对象对不对，可以拿一份事件日志算出来。这些都被推迟到整套模拟里一起暴露。
- **今后**：
  - 每个改动先用最快的那一级证明：单元断言 → 离线样本集 → 事件日志重算 → 短重放；
  - 模拟运行只用来出演示素材，不用来找问题；
  - 一次运行超过 10 分钟的验证，开跑前先写下要看的三个数字和预期，跑完对照。

### 2.3 世界和产品同时在变，结果说不清是谁造成的

- **实例**：
  - Q9.4 同一轮里，世界调了 v2，觉的家族在改，模拟人的提示词在改，泄露判断在改；
  - 送样失败 46% 一度被当成产品问题，查下来是世界参数（#26）；
  - 研发被压垮也是世界造成的（#25）。
- **原因**：每次运行都同时改了几处，出了问题无法归因。
- **今后**：
  - 一次验证只改一处；
  - 世界参数先写定、再跑对照，调过什么写进口径；
  - 正式数字的种子在调完之后另取。

### 2.4 证据过期而不自知

- **实例**：
  - v8 里多处数字来自改代码之前的运行；
  - 业务月数据换代码后不能重放；
  - 我上一轮汇报的旧线上意图正确数写错了（应为 22/45）；
  - 核对样本又用来调参（#39）。
- **原因**：数字产生之后没有记下它对应哪一版代码、哪一版世界；对外引用时也不回头核。
- **今后**：
  - 报告里每个数字写清楚出处：运行编号、提交、种子、日期；
  - 代码改动影响到某个数字时，在原处标「改前」，或者重跑；
  - 对人汇报的数字从文件里重算，不凭记忆。

### 2.5 节奏：大包、长时间不提交、待定事项堆积

- **实例**：
  - Q9.4 到「理解只在一处」连着四个包没有提交；
  - v8 每包都有「待人定」，越积越多；
  - 我中途还有一次越过「每包停下」继续往下做的倾向（记忆 `stop-after-each-workpackage`）。
- **原因**：包的边界按功能划，没有按「能单独证明、单独提交」划；整月模拟又把几个包绑在一起才能验收。
- **今后**：
  - 一个包的验收必须能在一小时内跑完；
  - 包做完先提交，再开下一个；
  - 待人定的事每次汇报列在最后，最多三条，按阻塞程度排。

## 4. 写法（v9 起）

沿用 AGENTS.md 铁律与 v8 收口方案的四条原则。另加五条，每条对应第 2 节的一种模式：

1. **先归位再修**：修之前写一句「这件事归谁」。语义只来自抽取或觉的打分。门面只拒绝三类情况。
2. **最快的证明优先**：先用单元断言、离线样本集或事件日志重算证明，模拟运行只出演示素材。
3. **一次只改一处**：世界、模型、提示词、门面不在同一次验证里一起改。
4. **数字带出处**：报告里每个数字写运行编号、提交、种子、日期。核对用的样本不拿来调参。
