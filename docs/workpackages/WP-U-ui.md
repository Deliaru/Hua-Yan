# WP-U 界面：业务员、产品经理、研发三个工作台

> 负责：A｜时段：5:45–7:15｜分支：`dev/a`

## 目标
用 Streamlit 把演示主线做成三视角工作台。每个工作台的主体是**和自己的角色助手对话**：人用自然语言指挥，助手调用工具、主动处理派单；旁边是只读的状态面板和确认卡。**界面上没有「起草」「发布」之类的流程按钮**——调度由助手完成；唯一能让结果生效的按钮是确认卡上的「确认」，那是委托人的签字。所有权限裁剪都在门面里完成。

## 依赖
WP-I（门面与 `app.agents` 完整）。

## 必读
`CONTRACTS.md` 第 ⑫、⑭ 节；`workpackages/README.md` 首版 Demo 验收；`docs/VISION.md` 第 4 节（三层角色）。

## 允许修改的范围
`src/huayan/ui/app.py`、`src/huayan/ui/common.py`、`src/huayan/ui/pages/1_业务员.py`、`2_产品经理.py`、`3_研发.py`

## 交付物与已定设计

### 1. 公共部分 `ui/app.py`、`ui/common.py`
- `HuayanApp` 放在 `st.cache_resource`；侧边栏：身份下拉框（来自 `actors`，无登录）、「新开一轮」（新 run）。
- **每页顶部状态条**（`app.status()`）：`模拟数据`｜种子是否占位｜Jev 实现（降级时标黄）｜觉实时模型｜抽取器｜角色助手（在线：大模型 fast / 离线）｜现场运行或记录回放。
- **对话组件**：`st.chat_message` 显示 `Conversation.messages`（system 消息用灰色，派单通知带问题 id）；`st.chat_input` 发给 `app.agents.chat`，之后调用 `app.tick()`；助手运行时显示 spinner。输入框上方的「下一句台词」只把 `demo/mainline.yaml` 中当前身份的下一句**填进输入框**，由人回车发送（演示辅助，不调度任何东西）。
- **确认卡组件**：`app.agents.pending(当前身份)` 中的每一条显示 `summary` 与参数，「确认」「拒绝」两个按钮 → `approve` / `reject` → `tick()`。
- **轨迹组件**（折叠）：`app.agents.trace(conv_id)`，每步显示工具、参数摘要、结果摘要；`blocked` 用醒目颜色显示「研发 R01 · L3：无权查看」。
- **需求条目组件**：每条显示文本、可展开的客户原话（`quotes`）、依据标签「{归属人} · {知识标题或『L3 转化知识』} · 被引用 n 次」、确认人。三个页面和 WP-E 的三层对照页共用。
- 离线（助手未运行）时，对话区显示「助手需要大模型（当前离线）」，状态面板照常显示已有数据。

### 2. 业务员工作台（L1）
- 选择或新建客户会话（选客户，这是上下文选择，不是调度）。
- 左：和业务员助手对话（「客户说……」「他这个能用在棉上吗」「帮他申请解密」）。
- 右（只读）：觉的追问提示（话术、概率）、场景需求卡（槽位、取值、原话）、推荐卡片（L1 版本）、被拦截的内容显示为「研发保密」；确认卡。

### 3. 产品经理工作台（L2）
- 左：和产品经理助手对话；派单通知（「觉发现机会汇聚……我已起草」）出现在这里。
- 右（只读）：问题队列（「Jev 升级」或「觉发现」、概率、`scored_by`、证据）；当前需求单（需求条目组件；L3 知识只显示归属人）；说明书草稿；确认卡；积分榜（`ledger.totals()`）。

### 4. 研发工作台（L3）
- 左：和研发助手对话（「第 2 条改成……沉淀成我的知识」「试样通过，对外可以说……」「这个解密可以，只给机理」）。
- 右（只读）：待转译 / 已确认的需求单（需求条目组件，所引知识原文可见）；会话完整内容（卡片 `internal` 版本）；确认卡；「我的知识」（`contributions`：被引用次数、被哪些需求单使用、积分）。

## 验收
按 `workpackages/README.md` 首版 Demo 验收第 1、3、4、6、7 条，在界面上只用对话和确认卡从头操作一遍（现场模式或记录回放）；录一段 3 分钟以内的屏幕录像或截图序列放进 `docs/assets/demo/`。

## 不做
