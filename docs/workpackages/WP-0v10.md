### C1：图片输入的最小差异

以下是供 V10.2 落实的约定，本小项不改契约源码。对照 [当前 Message](../../src/huayan/contracts/gateway.py) 与 [网关](../../src/huayan/gateway/client.py)，只增加三个内容类型，并扩大 `Message.content` 的联合类型：

```python
from typing import Literal
from huayan.contracts._base import BaseModel

class TextContent(BaseModel):
    type: Literal["text"] = "text"
    text: str

class ImageURL(BaseModel):
    url: str

class ImageContent(BaseModel):
    type: Literal["image_url"] = "image_url"
    image_url: ImageURL

# Message 中只替换原来的 content: str；其余字段不变。
content: str | list[TextContent | ImageContent]
```

`content` 仍必填；两个 `type` 默认值如上，其余新增字段必填。既有字符串消息的值与序列化结果保持不变，`LLMRequest`、`LLMResponse`、`complete/structured` 的签名和默认值不变。新增类与现有类型一样继承项目 `BaseModel`，不加重复类型校验。

调用示例（V10.2 实现上述类型后使用；`gateway` 是现有配置构建的网关）：

```python
from base64 import b64encode
from pathlib import Path
from huayan.contracts import LLMRequest, Message, Tier
from huayan.contracts.gateway import ImageContent, ImageURL, TextContent

image_path = Path("data/knowledge_v10/manifest/review/native/SRC-3a2130604c-p02.png")
image_url = "data:image/png;base64," + b64encode(image_path.read_bytes()).decode("ascii")
request = LLMRequest(
    tier=Tier.STRONG, caller="ingest:extract", temperature=0,
    messages=[Message(role="user", content=[
        TextContent(text="读取本页工艺曲线，分别保留原工艺与试样工艺、阶段及原单位；不清楚的标待补读。"),
        ImageContent(image_url=ImageURL(url=image_url)),
    ])],
)
response = gateway.complete(request)
```

送往现有 SDK 的 `messages[0].content` 是两个普通 JSON 对象：`{"type":"text","text":"…"}` 与 `{"type":"image_url","image_url":{"url":"data:image/png;base64,…"}}`。输出仍为现有 `LLMResponse`；实际模型、usage、fallback 来自网关响应。结构化读数通过同一个 `gateway.structured` 返回 V10.2 的读取侧类型，本包不预设读数结构。

实现仅需让 `_complete` 的消息装配使用 `message.model_dump(mode="json", include={"role", "content"})`，继续追加原有工具字段。缓存键已经包含整个 `req.model_dump(mode="json")`，图片字节随 data URI 进入现有指纹计算，无需另建图片缓存或哈希字段；现有无缓存配置照常适用。`MockGateway.complete` 的工具标签匹配只需按字符串/内容列表正常分支，列表仅拼接 `type="text"` 项；图片不产生模拟读数，仍明确标 `mock`。沿用既有计量、重试和错误处理，不将图片调用失败静默改成纯文本成功。

图片来自原生 Office 导出的 PNG 或其裁图；读取侧负责把本地字节编码为 data URI，不把磁盘路径当远程 URL。该例未发起模型请求，实际图片调用与相应回归归 V10.2。

### C4：读取位置映射到现有 Fragment

[Fragment](../../src/huayan/contracts/knowledge.py) 六个字段保持原样：`doc_id/span/text/level/source/fingerprint`，不增加 `meta`。读取侧保存下列最小定位信息；这是内部记录约定，不是新增公共契约或版本系统。

| 读取侧字段 | 含义 |
|---|---|
| `source_id` | 清单中的来源编号，映射为 `Fragment.doc_id`；本轮同一来源刷新时保持编号 |
| `file_sha256` | 本次读取的原件字节 SHA-256，沿用清单 `sha256`；不使用派生 PDF/DOCX 的摘要冒充原件 |
| `span` | 原生结构位置；首份报告使用 `table-1` 等从 1 开始的 `document.tables` 序号，段落用 `paragraph-N`；PPT 后续可用 `slide-N/shape-ID`，不含引用分隔符 `#`、`@` |
| `locations` | 原生预览位置列表，每项为 `page/image_path/bbox`；页码从 1 开始，跨页分别列出；`bbox=null` 表示整页，裁图时用对应原图左上角起算的像素框 `[left, top, right, bottom)` |
| `text` | 当前块的原生文本，保留表头、单位与原文异常；表格单元格用制表符、行用换行连接，不用模型总结替换 |

按 `(source_id, file_sha256, span)` 回到本次审阅的原件与预览，按 `(doc_id, span)` 取当前块交给现有编译/复核路径。原件与读取副本的对应指纹已在清单及结构核验文件中记录。来源内容刷新时重新读取；不要把旧的静态示例当成当前来源。

输入输出示例（`record` 为上述读取记录，`source` 为同一来源清单项）：

```python
from hashlib import sha256
from huayan.contracts import Fragment

fragment = Fragment(
    doc_id=record["source_id"], span=record["span"], text=record["text"],
    level=source["level"], source=source["source"],
    fingerprint=sha256(record["text"].encode("utf-8")).hexdigest()[:12],
)
evidence = f"{fragment.doc_id}#{fragment.span}@{fragment.fingerprint}"
```

真实输入、六字段输出及引用字符串见本地 `data/knowledge_v10/manifest/c1-c4-examples.json`：取首份报告原生 Word 读取副本的第1张表，对应原生预览第1页。文件指纹留在读取记录；`Fragment.fingerprint` 继续是文本 SHA-256 前12位，与 `FolderSource` 和 `compile.recheck` 的既有语义一致。

本例只演示定位映射。A/B、共同条件与阶段在 V10.2/V10.4 按原文分别读取和引用，不能靠一个表块自动补齐全部条件。图像读数引用对应页面/区域，保留辅助读取与待人工补读标识；原文引句、图像读数及派生计算分别记录，不把模型读数当成原生文本。内部来源保持 L3，归属与专业确认继续按用户要求暂缓。读取侧记录不写入 `qi_state.json`，权限和来源变化处理沿 G1/G3 的既有入口，由相关包接入。
