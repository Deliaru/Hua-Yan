非结构化知识
编译系统

把企业散落在报告、表格、实验记录和业务沟通中的知识，编译为带证据、保留条件、可授权复用的组织能力。
基于契 v3.3Evidence-grounded IRSemantic ETL动态 Schema能力授予与撤销

01核心主张

化言已经建立“依据 → 结论 → 能力”的知识治理框架。现在需要补齐的是从杂乱的非结构化资料中形成高质量候选结论的前端编译能力。

知识编译器负责发现、组织和验证候选知识；契负责确认、授权和运行；觉负责在业务过程中发现知识缺口与复核时机。
COMPILE

从资料到知识

保留原始证据、实验条件、语义关系和版本，生成可检查的候选知识。

AUTHORIZE

从知识到能力

专家确认结论，按场景授予追问、适用、转译、披露等能力。

REUSE

从能力到组织行动

业务 Agent 使用已授予的能力，记录使用结果，形成复用与更新闭环。

设计选择：保留契 v3.3 的三类对象和六种能力形式；新增一个轻量的编译期语义中间表示。数据加工与业务权限分别归属明确，现有化言流程继续运行。

知识编译前端

承担原始资料解析、候选事实归纳、动态 Schema 和语义检查。主要输出是可审查的候选 KnowledgeUnit。

契的能力编译后端

沿用 Fragment、KnowledgeUnit、Capability 的关系以及确认、授予、撤销、分层视图和审计机制。

编译过程允许大模型提出候选；正式专业结论由专家确认，业务执行能力由已授权的 Capability 提供。权限继续在知识库、披露网关和门面执行。

03证据解析：保存知识形成的上下文

传统定长切块容易拆开“实验结果”和“实验条件”。化言以 Evidence Block 作为编译期处理单元，保留原始结构与位置。

证据类型关键内容作用
TextBlock段落、标题层级、上下文恢复主张与论述语境
TableBlock表头、单元格、单位、合并关系保留实验参数与测量值
FigureBlock图注、图例、坐标轴、图像区域支持曲线和示意图理解
RecordBlock时间、主体、事件、结果组织沟通和试样历史
SourceMetadata文档 ID、版本、密级、定位、指纹支撑引用、复核与失效传播

企业已有 RAG 时，经 SourceAdapter 检索和回取原文；直接交付的资料由本地来源适配器管理。编译层持久保存证据指针和内容指纹，原文件由来源系统保管。

实现取舍：先支持 PDF、Excel 和纯文本。PDF 解析可选 Docling 或 MinerU2.5；表格结构与单位准确率优先于漂亮的纯文本输出。图表理解按实际资料比例追加。

04Knowledge IR：让专业知识可计算

这是编译系统的核心。每条候选知识不仅包含“实体—关系—对象”，还保留陈述性质、完整条件、限制范围及证据依赖。

Observation · 实验观察Assertion · 文档主张Constraint · 适用条件Recommendation · 业务建议
{
  "kind": "observation",
  "subject": {"type": "product", "id": "HY-LV206"},
  "predicate": "improves_color_uniformity",
  "conditions": {
    "all": [
      {"field": "fiber", "eq": "nylon"},
      {"field": "equipment", "eq": "overflow_dyeing"},
      {"field": "temperature_c", "lte": 80}
    ]
  },
  "evidence": [{
    "doc_id": "RPT-044", "version": "v2",
    "location": "table:2,row:3", "fingerprint": "sha256:..."
  }],
  "status": "candidate"
}

以上为结构设计示例。核心语义是：条件是知识的一部分。一个在特定设备、材料和温度下成立的实验观察，只能用于相应情境的后续判断。

适用情境的三种状态

已知情境状态系统行为
纯锦纶 + 溢流染色机 + 75℃确认适用完整命中已授予情境，可确定推荐
纯锦纶 + 溢流染色机 + 温度未知可能适用提示缺失的温度条件，保留条件性建议
纯锦纶 + 气流染色机 + 75℃未覆盖按新情境交给专业流程处理

契 v3.3 已经提出完整情境和“可能/确认适用”；本方案为 applicable 增加基础比较、AND/OR、区间和单位支持，使数值参数也能进入同一套授权机制。

05动态 Schema：从资料中发现新的分类和关系

采用“固定业务核心 + 证据驱动扩展”。核心结构维护化言既有产品、现象、槽位、实验和业务对象；扩展结构从新资料中发现专业别名、故障类型、工艺概念和测量指标。

固定核心 Schema

Product、Phenomenon、Process、Equipment、Material、Experiment、Condition、Result、Evidence。

保证与现有三层转译、产品适用和契的能力形式对齐。

候选扩展 Schema

新产品别名、新工艺类别、专业现象分组、新实验指标。

每项扩展携带出处、已有概念的对应关系、冲突与待批准状态。

跨文档归纳的具体价值

例如 20 份客户反馈都提及“洗后发硬”。系统先归集面料、洗涤条件、产品批次和反馈时间，再提议共同问题模式；由专业人员确认后才形成组织知识。这使散落的反馈逐渐变成可比较、可追踪的产品改进线索。

技术路线：借鉴 SCION 的证据约束 Schema 归纳与 AutoSchemaKG 的开放概念发现。第一版聚焦实体别名、概念归并和跨文档聚类，暂不增加通用本体编辑器。

06语义验证：守住知识编译的边界

语义检查围绕三个可测试的要求展开：证据找得到、条件保得住、适用范围不扩大。

检查项执行方法失败结果
证据完整性重新 fetch 原始片段，核对定位与指纹候选退回编译报告
实体一致性产品编号优先，别名保留候选状态等待确认实体映射
条件完整性原文限定条件与 IR 条件逐项核对阻止编译为执行能力
数值与单位统一单位，检查范围和比较方向提示具体字段错误
版本与矛盾同实体、同指标、可比条件下比较结果生成复核候选
依赖传播依据 → 结论 → 能力的引用索引挂起受影响能力

示例：两个实验结果看起来矛盾

来源产品温度观察结果
实验 ALV20675℃色花改善
实验 BLV20685℃效果不稳定

编译器先识别温度差异并保留两个观察，再归纳“性能可能具有温度依赖性”的研究假设。只有同条件下出现不一致，才优先进入冲突复核队列。

07编译到“契”：从候选结论到授权能力

正式知识继续使用契的 KnowledgeUnit；运行行为继续由契的六种 Capability 驱动。Knowledge IR 完成语义加工后，向这套稳定接口输出。

知识编译结果Capability使用位置
客户术语、领域别名phrase客户语言 → 槽位/现象
关键缺失工艺条件ask觉的追问与研发回问
完整产品适用情境applicable产品候选与确认适用
场景语言与专业语言映射translationL1/L2/L3 分层转译
批准披露的专业表述statement推荐卡片、对外说明
客户专属披露授权decrypt披露网关

编译路径是：证据抽取 → 候选结论 → 专家确认 → 能力提议 → 按层级授予 → 运行视图。跨层授权沿用契 v3.3 的归属人签字与产品适用范围批准。

研发的一次专业确认，可以沉淀为组织长期使用的能力；授权范围、使用记录与撤销权始终跟随这项能力。

08知识编译进入化言业务闭环

01

业务发现缺口

客户提出一个现有能力无法确定解决的工艺问题。

02

定向编译知识

Agent 根据问题检索资料，提议新的证据、结论和适用情境。

03

专家确认与授予

研发确认技术结论，必要时经产品经理批准新的适用范围。

04

前台持续复用

后续同情境可直接使用能力，使用与反馈进入事件日志。

觉持续观察知识缺口、重复回问、能力失效与客户反馈，提出 qi_grant 或 qi_review 等决策。觉负责发现时机；角色 Agent 负责准备；专家负责签字；契负责生效。

首次接入可按文档清单完成一轮资料抽取。正式能力审核集中在实际业务需要的候选知识上，使研发审阅量随真实需求增长。

09实现路径：四个可验收阶段

阶段本阶段交付完成标准
阶段 1
解析与 IR		SourceAdapter、PDF/Excel 解析、Evidence Block、Knowledge IR、证据定位从一组技术资料稳定提取带条件的候选事实
阶段 2
接入契		候选 KnowledgeUnit、六种能力提议、条件表达、专家确认与授予同一产品在不同授权情境下返回正确适用状态
阶段 3
知识归纳		别名识别、跨文档关联、候选 Schema、冲突检查、依赖索引能发现重复问题并定位影响该结论的原始资料
阶段 4
业务回流		缺口驱动的定向编译、qi_grant/qi_review、使用事件、撤销传播完成“首次专家判断 → 后续复用 → 证据失效 → 停用复核”链路

具体工程取舍

  • 继续使用 Python、Pydantic 和化言现有模型网关，新增代码集中在 src/huayan/ingest/。
  • 编译期采用函数式算子：parse → extract → normalize → join → verify → lower。
  • 复用现有知识单元 ID、事件日志、权限引擎、披露网关和门面接口。
  • 实体关联与证据依赖先用轻量引用索引；查询规模达到实际瓶颈再评估图数据库。
  • 文档批量处理采用任务队列或离线脚本；运行时只查询已生效的能力视图。
  • 避免引入新的 Agent 框架、独立授权服务和通用可视化本体平台。

10验收与对照实验

用同一批产品说明书、实验记录、表格、客户反馈建立三组对照，并加入刻意设计的条件陷阱。

BASELINE A

普通 RAG

解析、检索、模型回答。

BASELINE B

契的基础编译

片段抽取、候选结论、专家确认、能力授予。

PROPOSAL C

语义编译 + 契

结构恢复、条件验证、知识归纳、能力授予及依赖管理。

评估指标评价目标
证据定位正确率输出结论可以回到对应文档、表格或段落
关键条件保留率温度、设备、材料、用量、工艺约束被完整保留
候选事实准确率抽取陈述与原文一致
超范围确定推荐数所有确定推荐均命中已授予的完整情境
跨文档归纳准确率合并的是相同问题，保留不同条件的区别
专家审阅成本每形成一条可用能力所需的审阅操作与时间
重复研发介入次数已授权情境在后续咨询中得到直接复用
失效传播正确率证据变化、结论撤回、能力撤销后正确停止使用
重点测试样本：同产品不同温度结论、相似但不相同的工艺、实体别名歧义、旧版与新版冲突、缺少关键槽位的客户请求、仅在部分情境下有效的产品。

11最终技术主张

化言让非结构化知识经历“证据解析 → 语义编译 → 专业确认 → 能力授予”，将沉睡在企业文档和专家经验中的判断，变成有来源、有条件、有归属、可复用的组织能力。

整个架构由三项能力共同支撑：知识编译器组织证据与候选知识，契管理专业判断的使用权，觉发现这些判断应该在哪些业务时刻被创建、复核和使用。

首要研发投入集中在 Knowledge IR、动态 Schema 归纳、条件完整性验证和需求驱动编译。优先把复杂化工资料变成准确的候选知识，再让这些知识在化言现有业务链中真正发挥作用。

知识有来源判断有边界能力有归属使用可追踪授权可撤销
