- **本轮源码核对**：说明固定版本中有什么入口、判断与数据来源，能定位现有路径；不等于重新完成端到端运行。
- **仓库 V9.1—V9.6 完成记录**：执行 Agent 记录的实际模型走查、截图位置和测试结果。试用资料、实际配置与截图位于未入库的 `data/pilot/`，本轮没有取得这些原始材料。
- **分享聊天中的上次 review**：当时助手报告在同一 `94d5a88` 上，以离线业务夹具补做定向复现。本轮将其与源码对应起来；具体复现过程和结果仍归属于上次 review，不冒充本轮实测。[上次 review][chat]

V9.6 记录与上次 review 都报告现有 **22 项测试通过**；V9.6 还记录前端构建通过。它们说明当时已有检查通过，不能抵消未覆盖分支的问题，也不是本轮重跑的结果。

## 二、已经做到哪里

### 共享协作底座已建立

试用启动方式 `--trial` 让不同浏览器使用同一份业务与固定运行目录；身份由服务端绑定，试用使用真实时钟。换模型配置保留业务，模型等待时其他人可以继续操作；后台准备失败可见、可重试，重启后未完成事项重新派发。代码中已有这些路径，V9.1、V9.2 记录了相应走查。[试用服务][server]、[应用门面][app]

助手支持按业务对象组织上下文，并用对象中的实际草稿检查是否准备完成。V9.3 把页面当前回问传给抽取入口，解决“客户说不清楚，却不知道在回答哪个条件”的输入缺口。V9.5 能保留暂时无法结构化的专业限制原文，并在正常推荐路径中把相关需求交回专业判断。这些属于面向真实使用的实质进展。[助手上下文][hub]、[完成记录][replan]

### 主业务链有开发者走查记录

V9.6 的 `v96` 记录覆盖：需求澄清、研发判断已有产品适用、真人产品经理角色批准范围、同条件的下一位客户获得推荐；条件改变后进入研发，经历回问、试样、评价、发布，再由后续客户复用；也检查了授予、撤销和撤销后的继续处理。

这次使用真实模型，**研发判断、试样结果、客户评价由开发者模拟**，不能称为四类真实岗位已经完成企业业务试用。V9.7 真人试用、V9.8 展示回填尚未见完成记录。机会汇聚和判断过时在这次走查中没有触发，冻结后的行为也没有在这次业务里运行验证。[V9.6 记录][replan]

真人试用要回答的，是业务员能否带着客户把事情说清，产品经理能否作出产品与商业判断，研发能否基于正确材料处理问题，负责人能否在权限内掌握进展和处理例外。项目方讲解、补资料和失败重跑可以如实记录；关键专业判断仍应由相应岗位作出。四个角色页面都存在、开发者点击过全部按钮，不能代替这层证据。

### 觉的机制与学习效果要分别说明

试用模型卡和特征文件只列出两个实际加载的学习格：`opportunity|L2`、`stale_capability|L3`。追问、回问、试样风险因部分特征与试用种子不匹配而回退；泄露风险因现行状态不再产生旧特征而回退；实时觉仍使用原型。此次走查的推进主要由规则评分支持。[试用模型卡][model]

这能支持主动提出事项、准备材料、人工判断和结案的运行机制，不能证明“学习式觉已经比规则少漏报、少打扰”。整格停用是当时的试用取舍，也不等于已经证明模型整体无法迁移；字段改名、特征含义变化和真正的新业务规律需要区分。

## 三、当前需要处理的业务缺口

以下记录问题及其影响，供执行 Agent 判断具体修法；不预定新的框架、数据结构或施工顺序。

### 1. 条件修正尚未贯穿草稿、试样与发布

**V9.6 已观察到**：客户补完回问后，产品需求与化学要点未更新，放出的内容漏了“溢流”。

**上次 review 离线复现到**：客户补入“无 APEO”后，结构化条件已正确更新，旧产品稿和旧化学稿仍可被视为准备完成；另一次流程先在气流设备下试样通过，后纠正为溢流、重新试样并获评价通过，最终发布却仍使用首次通过试样的气流条件。

**本轮源码可对应的原因**：`add_turn` 只对 `draft` 状态清理自动产品稿，返工后的 `rd_accepted` 没有同样处理；准备检查主要看材料是否存在；`release_product` 取历史第一条通过试样，说明书用法又读取产品稿。[应用门面][app]、[说明书包装][translate]

这不是抽取模型有没有听懂的问题。当前应让客户最新条件、重新确认的专业材料、本轮获认可的试样及发布能力相互对应。保留人的专业修改，同时让受条件变化影响的部分被重新看见。上次 review 也说明某条离线 Agent 路径会重做化学稿，因此不能写成每次都会留下旧化学稿。

### 2. 推荐消费端没有完整遵守能力有效性

**上次 review 复现了两条分支，本轮源码仍能定位对应路径**：

- 原推荐依赖的无限制能力撤销后，只剩同产品、同结构化条件但附专业限制的能力，旧推荐仍保留，引用仍指向已撤销能力。正常推荐考虑 `limits`，失效检查的另一次匹配未带同样限制。
- 研发直接审定给原客户的推荐保存为 `candidates=[]`。专业结论撤回、依赖能力挂起后，失效检查从候选中找不到依据，跳过了这张推荐。[推荐与失效处理][app]

应检查每张当前推荐依据什么有效判断成立；自动推荐、研发审定推荐及撤销重算需要一致使用条件、限制和当前引用。这里不要求扩大成全量依赖传播。

**撤销某项使用授权，与撤回专业结论本身是两种动作。**停止“适用推荐”授权，不当然要求撤销同一结论下所有可说内容；现有 `withdraw_claim` 已有挂起相关能力的语义。要解决的是具体消费入口遗漏，不能把一切级联撤回写成新需求。

### 3. 共享角色入口有两处权限遗漏

上次 review 报告：不能查看他人客户会话的 C02、S02，仍可向该会话调用 `/api/turn`；C02 直接读研发 L3 知识被拒，但读取研发助手 trace 时能取得工具结果中的机理文本。

本轮静态核对确认：试用入口虽补入服务端身份，`/api/turn` 仍只把会话、发言角色和文字交给 `add_turn`，没有传递操作者做目标会话归属检查；`/api/agents/trace` 只按对话编号读取，没有访问者检查。[试用 API][server]、[trace 查询][hub]

这是现有权限体系在具体入口的遗漏，需要在真实多人试用前处理。界面没有提供越权按钮，不能替代服务端限制。

### 4. 觉有可定位的遗漏与误报

**遗漏**：当前试样风险规则只数客户明确答过“不清楚”的必需条件。状态已有 `missing:*` 与 `unknown:*`，规则却只看后者；上次离线复现中，未问到的必需条件得 0 分，明确不知道得 0.6。V9.6 的加工形态漏问与此一致。[风险状态][state]、[试样风险规则][risk]

这是既有结构化事实的使用缺口，可以直接校正，不必等所有模型重训。识别“已规定必需而尚未取得”，与在下游用关键词重新猜客户含义，是两件事。

**误报**：V9.6 与上次 review 都观察到正常问用量、同浴、客户解释也触发泄露风险。规则把搜索内部命中的上层存根、已授予结论的集中度当成异常行为。现在提出的是**需要负责人签字的冻结建议**，不是已经自动冻结；冷却后旧证据仍可能重复触发。[泄露风险规则][leak]

试用前需要决定如何停用或改正这类已知错误提示。上次 review 建议先停发该建议；它是待采纳的处置意见，不是本轮已经执行或用户已经确认的决定。

### 5. 成果应回到原业务，资料缺失不能变成无限制

V9.6 记录发布后业务员页仍显示“已转研发”；上次 review 进一步复现原客户会话仍为 `escalated`、没有新成果推荐。下一位客户能够复用，尚不能代替原业务员与原客户收到本单结果。

目录中 WA 的空适用范围导致错误推荐，TF-217A 原文“锦纶及其混纺”被起草成只限锦纶。具体适用范围由产品经理和专业人员确认；**尚未取得或未确认的限制，不等于确认无限制**。当前匹配将空条件视为无约束，本轮源码能核对这一语义。[匹配逻辑][domain]

新产品还可能沿用“在研项目”名称、同现象首个产品类别及“未转译”机理文案，应形成可理解的正式业务成果。产品编号显示、一般文案可随使用调整。业务对象续跑也不等于助手聊天和 trace 全部恢复；上次 review 报告后两者未从文件重载，本轮未做重启实测。

## 四、最小证据台账与文档要求

| 证据 | 可以证明 | 不能代替 |
|---|---|---|
| 固定版本源码 | 实现路径、数据来源与权限检查位置 | 真实运行效果 |
| V9.1—V9.6 完成记录 | 开发者记录的模型走查与具体改动 | 真人岗位使用及独立复测 |
| 上次 review 的离线复现 | 同版本若干组合分支存在问题 | 真实资料下所有路径的结论 |
| 试用模型卡与特征文件 | 哪些学习格被保留、哪些回退 | 本次业务中的学习增益 |
| 历史模拟报告 | 对应版本、数据与口径下的局部结果 | 企业实际工时、返工率和经营收益 |
| 后续真人试用记录 | 岗位能否办完事、哪里仍需帮助 | 长期研发产出与持续收益 |

当前入口要统一指向工作分支。README、ARCHITECTURE 中“尚待建立共享实例”的旧现状应更新；工作包索引“v5 当前”应标为历史。愿景保留完整的组织价值与技术远景，架构解释职责，状态文档承接证据和缺口，执行计划处理当前工作，避免每份文件重复混写全部历史。

这些缺口共同影响的是已经承诺的业务结果：同一需求的条件传到底，同一判断始终在有效范围内使用，同一主体只处理有权处理的信息。因此需要成套处理相关路径，但不意味着推倒共享底座、建立新的通用权限平台或等待全部学习家族训练完毕。新框架和新模块是否必要，仍由执行 Agent 根据实际阻断判断；本说明没有把它们列为试用前置条件。

## 五、哪些证据适合进入 PPT

当前可展示：同一专业判断怎样改变下一次业务，业务员、产品经理、研发分别减少了哪类重复工作；觉如何提出、维持并推动事项得到处理；契怎样承载判断的来源、条件、归属和使用。用现有案例、流程图及有代表性的截图支撑讲述，PPT 应独立成立。

真实试用后再补：谁实际作了判断、哪次判断被复用、哪些条件遗漏被及时发现、人员仍在哪些地方需要帮助。产品经理的需求转化经验也属于组织积累，不能只计算研发贡献。

**不把历史模拟数字改名成真实企业收益，不把 22 项测试改写成“全部可靠”，不把开发者扮演四岗位写成真人试用，不把两个学习格已加载写成学习效果已证实。**“少重复判断、减少可避免返工、释放中长期研发精力”可以作为有因果逻辑的价值主张；实际幅度按试用与后续运营数据说明。
