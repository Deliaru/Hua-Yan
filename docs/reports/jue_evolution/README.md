## 安全对照

**结构层**：W1–W4 客户自助会话里的 pH 追问次数（全部种子合计）：frozen 0，evolving 0，unfiltered 0；授予 K3 之后同一批色花客户：frozen 179，evolving 179，unfiltered 33。未授予时客户层视图里没有 pH，`ask_slot` 的前置条件不成立，不论训练时过滤与否、模型分数多高都提不出来；客户层能问什么由视图决定，学习改不了。

**校准层**：重训后（W2–W4）同一组客户层追问对象上，两种模型的排序一致性（Spearman）平均 0.949，过阈值个数 evolving 平均 146.5、unfiltered 平均 122.5。按层过滤保护的是校准：研发层的结果不改变客户层追问的排序与次数；上表「不按层过滤会怎样」是它对结果的影响。

研发为同一类需求反复回问 pH 的那些单，在按层过滤下不进入客户层追问的训练，只作为觉提出 `qi_grant`（把「问 pH」授予客户层）的理由，由研发签字决定。

## 结论（照数据写）

- **进化没有让觉「更快问全」**：两种完整率三组完全相同——客户层视图内的必问条件由前置条件保证一定会问，研发视图的必问条件（pH）被客户层视图挡住，学习两头都改变不了。
- 进化的作用很小：W4 evolving 比 frozen 正确处理率 +0.017、错误推荐率 -0.020，代价是平均多问 +0.37 次；1 / 5 个种子上正确处理率没有变化。
- 客户层追问格（ask_slot|L0）到 W4 换上模型的种子数：evolving 0 / 5，unfiltered 5 / 5。按层过滤后客户层这一格数据少，没胜过规则；不过滤的合并格数据多，更容易胜出。
- **未授予时，不过滤也学不到客户层不该问的东西**：pH 不在客户层视图里，结构上提不出。
- **授予后，不过滤会少问已授予的条件**：客户层 pH 追问 unfiltered 33 次、evolving 179 次；错误推荐率 unfiltered 0.015、evolving 0.000（5 个种子共 200 位色花客户）。研发层的结果混进客户层的训练，会改变客户层对已授予条件的排序；按层过滤守住的是这一点，代价是客户层这一格数据少、学得慢。
