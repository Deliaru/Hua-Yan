# OneJev 区分度探针：原始事件证据能不能让觉看到规则看不到的东西

> 全部为模拟数据：占位种子 + 7 个生成的业务周（make_jue_k_data 的 test 周 w34～w39，以及留出周 `data/week/w1`），在真实链路上跑出事件（抽取规则、Jev 桩）。OneJev-9B 零样本，部署在 AutoDL RTX 5090。
> 复现：`uv run python scripts/probe_onejev.py`（需要 OneJev 服务，约 1052 次调用，十余分钟）。数字见 `metrics.json`，逐样本见 `samples.jsonl`。

## 问的问题

觉应当监控全过程信息流。现在原型交给 OneJev 的状态只有对象的五六个统计数，和规则看到的一样。把窗口内的原始事件（客户原话、提问文本、试样记录）作为证据一起交给 OneJev，区分度会不会提高？

## 做法

样本按 JUE WP-P：每条注入在 `[earliest, latest]` 内取 3 个扫描时刻为正例，每条困难负样本在其窗口内取 3 个时刻，另每周抽 15 个不在注入清单里的同类对象为平静负样本。注入外已有 ≥ 2 位客户升级的主题按觉的定义本身就是机会汇聚，单列为 natural，不进 AUC。正例 63、困难负样本 60、平静负样本 105、natural 298。AUC 区间按样本组（同一注入 / 同一对象）bootstrap。

| 打分 | 状态 | 题面 |
|---|---|---|
| 规则 | — | 模板 `rule_score`，前置条件不通过记 0 |
| 只看属性 | 对象属性 | 现有 `worth_prompt`（= 今天的「原型 + OneJev」） |
| 证据 · 中性题面 | 属性 + 原始事件证据 | 只陈述要做的决定，不给判断依据 |
| 证据 · 业务背景题面 | 属性 + 原始事件证据 | 现有 `worth_prompt` |

## 结果

| AUC（正例 vs 困难负样本） | 规则 | 只看属性 | 证据 · 中性题面 | 证据 · 业务背景题面 |
|---|---|---|---|---|
| 机会汇聚 | 1.000 | 1.000 | 0.847 [0.68, 0.98] | 0.925 [0.79, 1.00] |
| 知识冲突 | 1.000 | 1.000 | **0.000** | 1.000 |
| 泄露风险 | 0.898 [0.79, 1.00] | **1.000** | 0.918 [0.80, 1.00] | **1.000** |
| 三类合并 | 0.777 [0.59, 0.91] | 0.985 [0.96, 1.00] | 0.599 [0.41, 0.79] | 0.990 [0.97, 1.00] |

三类合并时规则分数的尺度各不相同，合并 AUC 偏低主要来自尺度，不代表单类区分度。

平均概率：

| | 只看属性 | 证据 · 中性题面 | 证据 · 业务背景题面 |
|---|---|---|---|
| 正例 | 0.70 | 0.32 | 0.75 |
| 困难负样本 | 0.55 | 0.32 | 0.53 |
| 平静负样本 | 0.52 | 0.29 | 0.51 |

## 结论（如实）

1. **证据没有带来增量。** 「证据 · 业务背景题面」与「只看属性」几乎相同（0.990 vs 0.985）。原因在数据：生成周里的注入本来就是按这几个统计数构造的，模拟文本又是模板句式，语言里没有统计数之外的信号。这次探针**证明不了**「看信息流有用」，也证明不了没用；要回答这个问题，需要「只有读懂语言才能判对」的样本（换着说法、不带关键词的套问，同一需求的不同说法，试样备注里的原因）。
2. **题面决定成败。** 中性题面下 OneJev 表现很差。知识冲突完全反了：产品原因失败 3 次平均只给 0.21，设备原因失败 1 次反而给 0.33。题面不点出「说明书声称适用这个条件」时，它不知道该拿证据跟什么比。零样本的 OneJev 依赖题面里给出的判断框架。
3. **OneJev 读属性比规则表达式更稳。** 泄露风险上，规则被检索噪声淹没的 `n_blocked` 带偏（0.898）；OneJev 读同一段题面会综合「要求讲原理的次数」，正例与困难负样本完全分开（1.000）。这是 OneJev 的优势，但来自读题面，不是来自证据。
4. **概率没有校准，不能直接拿 0.5 当阈值。** 平静负样本平均 0.52，105 个里有 80 个 ≥ 0.5；298 个 natural 主题全部 ≥ 0.5。前置条件一旦放宽，按 0.5 发布会大量打断人。要么保留前置条件，要么在验证周上拟合校准层、按代价定阈值。
5. 按 JUE WP-P 的决策线（按 AUC 区间下界），「只看属性」的下界 0.96 ≥ 0.75，属于「主要由 OneJev 判断」一档；但第 1、4 条说明，在现有模拟数据上这只说明 OneJev 能读懂这几个数，前置条件放宽前必须先解决校准。

## 限制

- 只有 7 个业务周，每类正例 21 个（7 条注入 × 3 个时刻），区间较宽。
- 平静负样本每周只抽 15 个；知识冲突的平静负样本只有 6 个。
- OneJev 每次只看一个对象；运行时原型是整快照多题一次提交，结果可能不同。
- 证据的格式、条数上限（主题 8 条、试样 10 条、提问 12 条）没有调过。
