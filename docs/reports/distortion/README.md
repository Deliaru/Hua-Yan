# 失真对照：需求到研发手里还剩多少、对不对

> 全部为模拟数据：占位种子 + `data/sim/cards.jsonl` 前 60 张程序生成的需求卡，模拟客户用模板模式，抽取、转译为规则实现；
> 觉与现场一致：Jue-K（`models/jue_k`，追问、回问均由 Jue-K 胜出），追问、回问阈值 0.15（`config/app.yaml` 的 `ask_jue_k`）。
> 复现：`uv run python scripts/make_single_card.py`（同时生成本页与单卡；约 3 秒，同一种子重跑结果逐字节一致）；`--n 300` 用 `run_distortion.py`。
> 数字见 `metrics.json`、`table.csv`，图 `distortion.png`。觉调用 169 次，**大模型调用 0 次**。

## 三组做法

同一张卡、同一个模拟客户随机种子（三组听到的开场白相同）：

| 组 | 做法 | 研发拿到什么 |
|---|---|---|
| G1 业务员转述 | 不用觉的提示，业务员按习惯只问面料，再凭印象写给研发 | 按**假设的转述噪声**加工后的现象和槽位，没有原话、没有依据 |
| G2 一次性翻译 | 不追问，只有客户开场白；用全部转化对照（L2、L3 混用、不按现象过滤）匹配一次 | 开场白抽到的槽位 + 直接产出的化学语言条目 |
| G3 化言 | 按觉的提示追问（最多 8 轮）→ L2 产品需求 → L3 化学语言需求单 → 对 L3 草稿**回问**（觉发现缺一个会改变转译的信息，问客户），回填后重新起草 L3 | L3 需求单（每条带客户原话与所引转化知识） |

另列「G3 化言（不含回问）」，即回问之前的 L3 草稿，用来看回问本身的作用。

## 结果（60 张卡）

**v7 重跑（2026-10-20）**：觉换成按「家族 × 判断层」重训的 `models/jue_k`（Q6），规则觉对照列也同批重跑（`jue_proto`，阈值 0.5，配置只改 `jue` 一节）。应升级的 41 张卡上的结论与 v5 单模型相同（Jue-K 19.5% / 90.9%，规则 65.9% / 75.8%）；L1 可解的卡与全部卡上两组都略有变化，下表已换成本次数字。错译率变化来自转化对照种子在 v6、v7 之间的调整，与觉无关。

|---|---|---|---|---|

| 槽位错误率 | 7.3% | 0.0% | 0.0% | 0.0% |
| 错译率（所引转化知识不属于该现象的条目） | —（不引用知识） | 6.6% | 0.0% | 0.0% |
| 平均追问次数 | 1.00 | 0 | 0.88 | 0.88 |
| 平均回问次数 / 其中事后有用 | — | — | — | 0.68 / 41.5% |

**按「需求会不会真的到研发」拆开**：本对照让每张卡都走到研发，但现实中只有 L1 解决不了、应升级的需求才会到研发。60 张卡里应升级的只有 5 张，所以另用 300 张卡（`--n 300`，41 张应升级）：

| 研发需退回比例（完整率） | G1 业务员转述 | G2 一次性翻译 | G3 化言（规则觉，对照） | **G3 化言（Jue-K）** |
|---|---|---|---|---|
| 应升级的卡，60 张中 5 张 | 80.0%（56.2%） | 100%（50.0%） | 100%（62.5%） | **0%（100%）** |
| 应升级的卡，300 张中 41 张 | 95.1%（49.2%） | 95.1%（50.8%） | 65.9%（75.8%） | **19.5%（90.9%）** |
| L1 可解的卡，300 张中 259 张 | 96.1%（45.8%） | 98.8%（42.2%） | 44.4%（84.9%） | 59.5%（78.1%） |
| 全部 300 张 | 96.0%（46.3%） | 98.3%（43.4%） | 47.3%（83.6%） | 54.0%（79.9%） |

- **真正到研发的需求，化言把退回比例从约 95% 降到 19.5%**：Jue-K 学到了「这个需求多半要升级时，研发要的必问信息此刻就该问」（追问标签含「应升级且为研发必问信息」，见 `docs/JUE_K_TRAINING.md` 第 3 节），应升级的卡平均追问 1.29 次，规则觉只问 0.80 次。
- **L1 可解的卡上 Jue-K 问得更少**（0.83 次 vs 1.22 次），这些卡在现实中不会到研发，所以被「退回」的多；只看全部卡的数字，规则觉（47.3%）好于 Jue-K（54.0%）。两组都如实列出，演示和材料以「应升级的卡」为准，并说明原因。
- 规则觉在应升级的卡上仍有 65.9% 被退回：必问但不影响 L1 候选的槽位（如「起皱印 × 面料」），规则分低于阈值，不问；回问只补「会改变 L3 转译」的槽位。
- 一次性翻译不追问，开场白里通常只有现象，必问槽位几乎全缺；不按现象过滤的转化对照会错配（6.6% 的条目引用了别的现象的知识）。它的「可回查」只能回到开场白一句。
- 回问把 60 张卡的完整率再提高 8.2 个百分点、退回比例降低 20 个百分点；应升级的卡上追问已经问全，回问不再改变结果。

**与上一版的变化**：上一版 G3 用规则觉（阈值 0.5），60 张卡退回 41.7%。本版按 Jue-K 的统计胜负判定改用 Jue-K（阈值 0.15），并做了两项设计调整：（1）追问标签加入「应升级且为研发必问信息」，（2）追问模板前置条件改为「会改变候选集，或是必问项」（原为「必问项且候选不止一个」，会话走向升级时研发的必问槽位过不了前置条件，规则和模型都问不了）。规则觉在新前置条件下结果不变（见上表对照列）。

## 必须说明的三点

1. **G1 的噪声来自假设参数**（`config/eval/distortion.yaml`）：现象被说成笼统的「染色有问题」0.3、每个已知槽位漏记 0.2、记错 0.1，业务员按习惯只问面料。依据是一线业务需求交流中的定性描述「客户和业务员不懂化学，只会描述宏观现象；业务员再加工转述，需求就变形了」，比例本身没有实测。企业数据到位后用真实转述样本替换。
2. **单卡对照是按固定规则选出的例子**（`docs/reports/single_card/`，与本报告同一次运行）：演示第一幕看的是那一张卡，证据是本页的统计。
3. **G3 的槽位错误率偏乐观**：模板客户与规则抽取共用种子中的口语说法表，客户说的话一定能被准确抽到，所以 G2、G3 的槽位错误率都是 0。真实对话中抽取会出错，这一项要用大模型扮演客户 + 大模型抽取再测。

## 局限
- 需求卡的槽位组合按面料 → 染料 → 染浴 pH / 工艺的相容表抽样（`huayan/sim/cards.py` 的 `COMPATIBLE`，印染常识，模拟假设）。
- 需求卡、客户都是模拟的；客户被问到才说、不会主动纠正。
- G3 只取觉的第一条提示追问，一次问一个槽位；回问最多 2 个槽位；觉为 Jue-K，阈值同 `config/app.yaml` 的 `ask_jue_k`。
- 应升级的卡只占约 14%，60 张卡里只有 5 张；拆开的结论以 300 张卡为准。
- 未做可选的大模型附加列（G2 换真大模型一次性翻译、G3 由助手在规则骨架上修改）。
