# 研发负责人与 CEO 试用说明

V10首份报告当前状态和四岗位安排见 [四岗位交接](first-report-v10.md)，本轮实际查看与反馈按 [记录模板](v10-session-template.md) 填写。

## 1. 打开收件箱

选身份时点「研发负责人」下面你的名字（研发负责人选「主管赵总」，CEO 选「CEO」），进入「研发负责人」工作面。你可以在业务处理之后再来查看，时间不限。左栏：

- **待签 / 准备中**：觉提出、需要你决定的例外事项。试用里通常是空的；
- **进展**：全部未合并的需求单，点开看前情和需求轨迹，掌握每张单走到哪一步、在等谁。

## 2. 处理第一件事

点「进展」里最上面一张单，从前情看它从哪位客户的哪句话来、经过了谁、现在在等谁。卡在某人那里太久，直接找那个人；需要你决定的例外会出现在「待签」里。

## 3. CEO 面

侧栏「CEO 面」把同一批客户需求放在两条流水线上：上面按传化原来的流程推算，下面是化言实际走过的路径（试用实例标「实测」，模拟业务月标「模拟」）。

- 第一屏是销售、产品经理、研发三个岗位的时间构成，从现状缩到化言；
- 三个头条数字：还给研发的时间、客户等第一个答复、一年多出来的钱。点「看算式」看每个数怎么算、用了哪些参数；
- 「按最保守参数」把差距往小里算；参数面板可以直接改人数、时薪、试样成本和每月询问量，标黄的是传化还没给、用假设值的；
- 流水线可以调倍速和来单量，点工位看停在那里的事，点一件看它走过的工位和旧流程会怎么走；
- 「撤销一条能力」是推演，不改任何状态：看用过这条能力的事改道交研发。

CEO 面只给计数、工位和人，不显示研发写的内容。

## 其他页面

- **觉视图**：选一张需求单，从客户提出需求到发布，觉每一次提出了什么、为什么提出、交给谁准备、谁签了字，都按时间列出。标「规则」的是模板规则打分，标「Jue-K」的是学习模型打分；
- **知识与积分**：谁的知识被引用、被复用，谁授予的能力被用了几次。

原来有一类「某位业务员的检索集中在同一产品的研发知识上，要不要冻结他的上层知识检索」：它会把正常跟单误报出来，**试用里不提出**。信息控制由分层访问、授予和撤销负责。

试用里的人名和标「模拟」的内容都是模拟数据。
