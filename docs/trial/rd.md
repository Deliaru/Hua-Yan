# 研发试用说明

V10首份报告的“本人资料候选”、固定指纹审阅与真实签字安排见 [四岗位交接](first-report-v10.md)，实际结果按 [记录模板](v10-session-template.md) 填写。

## 1. 打开收件箱

选身份时点「研发」下面你的名字，进入「研发」工作面。左栏就是你的收件箱：

- **待签**：Agent 已经准备好、等你签字的决策（橙色），后面的数字是几项；
- **准备中**：你的 Agent 或产品经理 Agent 正在起草的，写着它在做什么；模型接口失败没准备成的，写明原因，可以整项重跑；
- **资料审阅**：「本人资料候选」是从你的报告读出、等你确认的结论；「我授予的能力」是你签过、正在被使用的判断；
- **需求单**：派给你的单子。

## 2. 处理第一件事

点「待签」里最上面一件：

1. 签字区在工作面顶部，下面依次是前情、需求轨迹和单头。需求转到你这里时已经带着客户原话和已问清的条件，产品经理 Agent 写好了产品需求，也查过有没有现成产品可用；
2. 你只做专业判断：选接单、不立项、回问或退回（见下）；草稿都由 Agent 起草，生效靠你签字；
3. 如果单上有你的报告编译出的资料候选，判「已有产品适用」时可以勾选作依据，先读审阅原文再签。签过的判断经产品经理批准适用范围后，下一位同样条件的客户就直接得到推荐，不再来找你。

资料来源改版时，「待签」里会出现复核：读本次原文，选「复核后保留」或撤回。复核前，依赖这条结论的能力会先停用，用过它的客户改道交给你。

## 一张需求单怎么走

1. **接单**：看产品需求和客户原话，然后选一项：
   - 「接单立项」：要开发，立一个在研项目。
   - 「不立项：已有产品适用」：选出适用的产品，写理由。如果只在某些前提下适用，就把前提写进「限制条件」，客户自助时就不会被自动推荐。
   - 「先回问客户」：缺的条件只有客户知道，就勾选要问的条件。
   - 「退回」：产品需求写错了，退给产品经理纠偏。
2. **确认化学要点**：Agent 把产品需求转成化学语言（L3），你逐条检查改正，然后点「确认」。
3. **试样**：录入试样结果，用「试样通过」或「录入不通过」。不通过时，选出是客户条件缺失还是配方问题。条件缺失就「先回问」，然后「退回重新转译」。
4. **客户评价通过后**：选出哪些要点「封存」、哪些对外「放出」，签字。然后「保存说明书」，最后「审定发布」。接单时新立的项目，发布前要填写产品名称和类别。发布后，产品进入目录，提出这张单的客户会收到推荐，下一位同样条件的客户也会直接得到推荐。

客户在返工中更正或补充了条件，单上的条件会随之更新。Agent 起草的化学要点按新条件重新起草；您改过的条目会保留，退回说明里会提示您按新条件重新确认。

## 契（知识授予）相关

| 按钮 | 作用 |
|---|---|
| 签字授予这句话 | 下层被问到你的结论却答不了时，写一句他们可以说的话授予下去；不能写结论原文 |
| 签字确认所选结论 / 签字授予 | 把你的判断授予某一层使用 |
| 撤销 | 「我授予的能力」里任何一条都可以撤销。撤销后，正在用它的推荐会撤回并重新匹配，下一单不再用 |
| 收窄 | 适用判断只在部分条件下成立时，去掉不成立的条件 |
| 复核后保留 / 撤回结论 / 更新适用表 | 依据变了或试样集中失败时，复核你的结论 |
| 批准解密 / 拒绝 | 处理业务员替客户提的看原理申请 |
| 申请查看 | 同层研发的知识只显示归属，需要时向归属人申请 |
| 沉淀为我的知识 | 把你改过的转译存成你名下的知识，以后转译会引用 |

右侧「你的 Agent」可以调客户原话和案例、机理、实验记录，帮你起草和修改化学语言。

## 每件事都带着前情

点开任何一件事，最上面是「前情」：客户第一句原话，以及化言、Agent 和其他人已经做了什么，最后一行写现在在等谁。你接手时不用回头问前面的人。

右上角「演示说明」打开后，前情下面多一段「过去怎么做」：同一件事按原来的流程（客户 → 业务员记录 → 产品经理转述 → 研发 → 产品经理评价 → 业务员开单）要经过几个人、几次交接、大约多少工时。这是按参数推算的，标「推算」；传化还没给的参数用的是假设值，标「假设」。真实试用里不讲这次省了什么，只给这个对照。

右侧「你的 Agent」可以调客户原话和案例、机理、实验记录，帮你起草和修改化学语言。

**注意**：试用里标「模拟」的内容是项目方补的，不当作真实判断；试样结果请按实际情况录入。
