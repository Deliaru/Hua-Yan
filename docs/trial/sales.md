# 业务员试用说明

V10首份报告试用请先看 [四岗位交接](first-report-v10.md)，按 [记录模板](v10-session-template.md) 留下本轮实际操作、帮助与反馈。

## 1. 打开收件箱

打开项目方给的地址，在「选择你在这次试用中的身份」里点自己的名字，进入「业务员」工作面。刷新、重启都不用重选；要换人，点右上角名字 →「换一个身份…」。

左栏就是你的收件箱：

- **轮到你**：有决策等你处理的客户会话，后面的数字是待处理几项；
- **全部会话**：你负责的客户的所有会话。客户自己在客户页说的话，也会出现在这里。

## 2. 处理第一件事

点「轮到你」里最上面那段会话：

1. 先看前情：客户说了什么，化言已经问了什么、推荐了什么，现在为什么轮到你（比如客户要报价）；
2. 右侧「觉提出的决策 · 待你处理」写着要你决定的事，草稿已经由 Agent 准备好；
3. 回复客户：「发给客户」框里是 Agent 起草的回复，改好后点「发出」。

收件箱空着时，可以在左栏点「＋」开一个新会话，用「客户说」照客户原话录入，不要先替客户翻译。中间的场景需求卡列出化言已经听懂的条件，每条都带原话；缺了什么，觉会提示你问哪一项。

研发试样通过后，你会收到「客户评价」：按客户实际反馈点「通过」或「不通过」，写明客户怎么说。

## 每件事都带着前情

点开任何一件事，最上面是「前情」：客户第一句原话，以及化言、Agent 和其他人已经做了什么，最后一行写现在在等谁。你接手时不用回头问前面的人。

右上角「演示说明」打开后，前情下面多一段「过去怎么做」：同一件事按原来的流程（客户 → 业务员记录 → 产品经理转述 → 研发 → 产品经理评价 → 业务员开单）要经过几个人、几次交接、大约多少工时。这是按参数推算的，标「推算」；传化还没给的参数用的是假设值，标「假设」。真实试用里不讲这次省了什么，只给这个对照。

## 按钮是什么意思

| 按钮 | 作用 |
|---|---|
| 客户说 | 把客户原话录进会话，化言会重新理解需求 |
| 帮我回一句 | 让 Agent 按当前需求起草回复，只写进草稿，不会发出 |
| 发出 | 把草稿发给客户 |
| 直接推荐 | 按当前条件立刻匹配一次现有产品 |
| 转产品经理 Agent | 你签字确认现有产品解决不了，需求带着客户原话交给产品经理 Agent 转译，再直达研发 |
| 升级说明 | 转研发前补充一句给研发的说明（Agent 会先起草） |
| 申请解密 | 客户确实需要看原理时，替客户向研发申请，研发批准后推荐卡才包含原理 |
| 通过 / 不通过 | 试样后录入客户评价，不通过时勾选是哪项条件出了问题 |
| 接手 | 客户在自助页反复追问产品内部（原理、配方）时，由你接过来跟进：讲用法和公开信息，确有需要再申请解密 |
| 现在不需要 | 你判断这条提示现在不用处理；觉会记住，不会马上再提 |

右侧「你的 Agent」可以问说明书、用法、这个客户的需求还缺什么，也可以让它起草话术和升级说明。研发的知识它看不到内容，只会告诉你该找哪位研发。Agent 只起草，发出去要你点「发出」。

**注意**：试用里标「模拟」的内容是项目方补的，不当作真实判断；拿不准的请问现场陪同人员。
