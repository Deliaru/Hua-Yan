# 业务员试用说明

**入口**：打开项目方给的地址，在「选择你在这次试用中的身份」里点自己的名字。之后进入的就是「业务员」工作面，刷新、重启都不用重选。要换人，点右上角名字 →「换一个身份…」。

## 你要做的事

1. **录入客户需求**：在左栏「客户会话」点「＋」，选客户，开一个会话。在「沟通记录」里用「客户说」录入客户原话，尽量照客户的原话写，不要先替客户翻译。客户自己在客户页说的话，也会出现在你负责客户的会话里。
2. **看场景需求卡**：中间的卡片列出化言已经听懂的条件，每一条都带客户原话。缺了什么，右侧觉会提示你该问哪一项。
3. **回复客户**：「发给客户」框里是你的 Agent 起草的回复，改好后点「发出」。觉判断现有产品适用时，推荐卡会给出说明书和用法，可以直接讲给客户。
4. **处理觉提出的决策**：都在右侧「觉提出的决策 · 待你处理」里，见下表。
5. **试样后带回客户评价**：研发试样通过后，你会收到「客户评价」，按客户实际反馈点「通过」或「不通过」，并写明客户怎么说。

## 按钮是什么意思

| 按钮 | 作用 |
|---|---|
| 客户说 | 把客户原话录进会话，化言会重新理解需求 |
| 帮我回一句 | 让 Agent 按当前需求起草回复，只写进草稿，不会发出 |
| 发出 | 把草稿发给客户 |
| 直接推荐 | 按当前条件立刻匹配一次现有产品 |
| 转产品经理 Agent | 你签字确认现有产品解决不了，需求带着客户原话交给产品经理 Agent 转译，再直达研发 |
| 升级说明 | 转研发前补充一句给研发的说明（Agent 会先起草） |
| 申请解密 | 客户确实需要看原理时，替客户向研发申请，研发批准后推荐卡才包含原理 |
| 通过 / 不通过 | 试样后录入客户评价，不通过时勾选是哪项条件出了问题 |
| 接手 | 客户在自助页反复追问产品内部（原理、配方）时，由你接过来跟进：讲用法和公开信息，确有需要再申请解密 |
| 现在不需要 | 你判断这条提示现在不用处理；觉会记住，不会马上再提 |

## 右侧「你的 Agent」

可以问说明书、用法、这个客户的需求还缺什么，也可以让它起草话术和升级说明。研发的知识它看不到内容，只会告诉你该找哪位研发。Agent 只起草，发出去要你点「发出」。

**注意**：试用里标「模拟」的内容是项目方补的，不是真实结论；拿不准的请问现场陪同人员。
