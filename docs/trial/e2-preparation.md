# E2队友准备包：分流判断标注表

本轮只完成建设方案“把样本做成可以逐条下拉选择的标注表”。复用E1原话和追溯信息，提供六类路径、知识状态、判断主体和理由的填写位置；不获取外部资料、不代专业人员填答案，也不执行分流能力评测。E2交付后停下等审查，不进入E3。

## 1. 使用方法

```powershell
# 正式入口复用E1；没有实际样本时会生成空表，不能称为专业验收通过。
uv run --locked --no-sync python scripts/prepare_routing.py --out data/knowledge_v10/evaluations/E2/blank

# 独立合成演示：4条dev需求、其中一条按两个占位知识状态另建标注行。
uv run --locked --no-sync python scripts/prepare_routing.py --cases tests/fixtures/e1/synthetic-cases.yaml --labels tests/fixtures/e2/synthetic-labels.yaml --out data/knowledge_v10/validation/E2-preparation-20261103

# 打开输出目录的annotation-form.html，选择/填写后点击“导出草稿／标注JSON”。
# 将实际导出文件放入本地E2目录，再用--labels回读检查：
uv run --locked --no-sync python scripts/prepare_routing.py --cases data/knowledge_v10/evaluations/E1/cases.yaml --labels data/knowledge_v10/evaluations/E2/e2-annotations.json --out data/knowledge_v10/validation/E2-annotations-check
```

仅生成本地静态HTML与JSON，不启动服务器、连接外部服务或写入业务状态。关闭页面前须导出保存，页面无自动保存；导出的草稿可以继续检查，路径选择后信息不完整会由CLI明确拒绝。表中没有“默认正确答案”。本页含原话和内部信息，只留data，不公开发布。

## 2. 六类选项与判断阶段

| expected_path | 该标签表示什么 |
|---|---|
| 自助解决 | 当时主体可用的公开资料/已生效能力足以完成推荐 |
| 交业务员 | 已有技术答案，当前需要报价、采购等商务处理 |
| 复用 | 已有经确认且可用于该主体和条件的判断能服务本单 |
| 研发不立项 | 超出原标注范围，研发判断已有产品仍适用，不开发 |
| 入研 | 需要进入研发处理、开发或试样 |
| 产品机会 | 多件同类需求经判断合并为产品课题 |

选项逐字对应现有route_of路径。`追问中`是未完成状态，不加进六类金标，不强行改成“自助解决”或“入研”。需要研发签字才能确定终局的样本，后续比较只能先到“是否进入研发”阶段；不能用一张draft需求单证明已经作出了技术结论或不立项决定。产品机会也不能仅凭几句相似需求自动认定。

## 3. 与E1的关联及附表字段

E1原文件保持不变。E2用`case_id`关联E1，以`id`区分标注行；同一件需求在不同知识状态下可以有多行。附表顶层为`cases_fingerprint`、`split`、`labels`，输入指纹复用E1的backtest.fingerprint；原话/来源/kind/dev-heldout来自E1，不重复人工填写。

导入的标注编号保持原样；缺少附表的样本自动补草稿。默认编号`E2-{case_id}`若已被占用，就依次尝试`-2`、`-3`等后缀，避开所有已导入和本次已生成的编号；导入文件自身有重复编号仍会明确拒绝。

| 字段 | 填写要求 |
|---|---|
| id / case_id | 唯一标注行编号／E1样本编号，不另编客户原话 |
| expected_path | 六选一；未能判断时保持null，不用系统预测代填 |
| knowledge_state | 实际判断所依据的qi_state副本路径或固定编号，说明当时知识已授予到哪一步 |
| knowledge_state_sha256 | 当时副本的完整64位小写SHA-256；文件名相同不表示内容相同 |
| viewer | 代谁判断，如customer:C01或sales:S01；同一知识状态对不同主体可用能力不同 |
| basis | 该需求为什么应走所选路径，指向当时可用能力/条件/商业诉求；与E1抽取标注依据分别保留 |
| labeled_by / labeled_at | 实际标注人及岗位、实际带时区时间；不继承E1标注人、不预填专业确认 |

选择路径后上述依据、主体、状态与标注信息须齐全；检查器只核对格式，不读取或验证所指qi_state，不声称哈希相符或专业判断正确。知识快照的实际固定与接入由后续业务评测负责。

“同一句话在确认前可能入研、确认后可能复用”仅说明标注依赖知识状态，不是对每一件需求预设答案。必须同时考虑实际授予层级、当前有效状态、完整情境、温度和limits；不能因为存在某条结论就自动标为复用。

## 4. 分区、草稿与后续接续

默认仅导出dev。复用E1的来源分组检查，其他分区只核对元数据，不解析或导出其标注答案。`--split heldout`只在正式报告阶段显式使用；不把已用于调试的合成示例称为未见集。每次导入核对E1文件指纹和分区；原话文件变了应重新核对，不静默沿用旧标签。

若同一case_id在多个知识状态下出现，后续比较按“需求 × 状态 × 主体”分别运行，原始样本分母与标注行数分别报。未知条件、待补限制、仍在追问或知识状态缺失，都不能为凑齐六类结果而填答案。

本次报告只有准备分母、字段填写状态及来源信息，没有混淆矩阵、误转研发/漏转、模型或业务效果分数。模板中的合成占位知识状态不是实际qi_state，路径保持未选，不能作为专业金标。后续若验证模型能力，使用当前项目配置的真实模型与实际计量，不以mock替代。
