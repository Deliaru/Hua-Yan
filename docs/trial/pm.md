# 产品经理试用说明

V10首份报告的专业范围与批准安排见 [四岗位交接](first-report-v10.md)，实际操作按 [记录模板](v10-session-template.md) 填写；没有待批准事项时如实记录。

## 1. 打开收件箱

选身份时点「产品经理」下面你的名字，进入「产品经理」工作面。逐单把客户需求转成产品需求的工作，由产品经理 Agent 在后台完成，你不用每单转述。左栏就是你的收件箱，只有三类需要产品判断的事：

| 左栏分组 | 什么时候出现 | 你要判断什么 |
|---|---|---|
| 适用范围待定 | 研发判「已有产品适用」，产品适用的条件要扩大 | 这个产品的适用范围要不要按研发的判断扩大。扩大后，同样条件的客户自助就能直接得到推荐 |
| 产品机会 | 同一类需求反复转研发，又没有产品可用 | 值不值得把几个客户的需求合并成一个研发课题 |
| 待纠偏 | 研发把产品经理 Agent 写的需求退回 | 改正有问题的条目，再交回研发 |

橙色标签是 Agent 已经准备好、等你签字的；写着「Agent 准备中」的还在起草。下面「Agent 后台转译中」列出正在转译的需求单，只供了解，不用处理。

## 2. 处理第一件事

点左栏最上面一件橙色的事：

1. 先看需求轨迹和前情：这件事从哪位客户的哪句话来，研发判了什么（扩范围的卡片上列出适用条件和研发写的限制）；
2. 签字：扩范围点「扩展适用范围」，产品机会点「合并为一个课题」并写一句商业判断，纠偏改好后点「修改完成，交研发」；
3. 不需要处理就点「现在不需要」，写明原因。

收件箱空着说明没有要你判断的事，这是正常的：业务员和研发之间的逐单转述已经不经过你。

## 每件事都带着前情

点开任何一件事，最上面是「前情」：客户第一句原话，以及化言、Agent 和其他人已经做了什么，最后一行写现在在等谁。你接手时不用回头问前面的人。

右上角「演示说明」打开后，前情下面多一段「过去怎么做」：同一件事按原来的流程（客户 → 业务员记录 → 产品经理转述 → 研发 → 产品经理评价 → 业务员开单）要经过几个人、几次交接、大约多少工时。这是按参数推算的，标「推算」；传化还没给的参数用的是假设值，标「假设」。真实试用里不讲这次省了什么，只给这个对照。

## 按钮是什么意思

| 按钮 | 作用 |
|---|---|
| 扩展适用范围 | 签字同意按研发的判断扩大适用范围，卡片上列出了适用条件和研发写的限制 |
| 合并为一个课题 | 把几个客户的同类需求合成一张研发需求单 |
| 保存 | 保存你对某条产品需求的修改 |
| 修改完成，交研发 | 纠偏改好，交给研发重新接单 |
| 沉淀为我的知识 | 把你改出来的「客户说法 → 产品需求说法」存成你名下的知识，以后 Agent 转译会引用，并给你记贡献 |
| 现在不需要 | 这件事现在不处理 |

右侧「你的判断产生了什么」统计 Agent 替你省下的转述，以及你的判断之后自动解决了多少需求。「觉视图」可以按需求单看觉在这条线上每一次提出了什么、交给了谁、谁签了字。

**注意**：试用里标「模拟」的内容是项目方补的，不当作真实判断；拿不准的请问现场陪同人员。
