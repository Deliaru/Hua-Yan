# 化言决赛路演 PPT 制作细纲 V6

19 页 · 主讲约 9 分 30 秒 · 现场 Demo 10 分钟 · 2026-11-04

在 V5 细纲上改了四件事：

1. 补上对手。开场先讲今天的 AI 和 Agent 缺什么，觉和契才有来由。
2. 觉和契各讲两页。第一页讲它是什么、为什么别人没有；第二页讲它怎么做到、凭什么可信。内容取自 `docs/觉：PREVIEW_STANDALONE (1).html`、`docs/契：带密级与归属的诊断契约编译器-对外介绍.html`、`docs/化言_从岗位智能到组织智能_完整介绍.html` 和 `docs/非结构化知识设计.html`。
3. 补上钱和落地。「钱从哪里来」「六周在传化跑通一条产品线」两页，回答 10-26 对接会上被追问的接入、担责、数据和分层。
4. 上屏用「业务动作 + 参数边界 + 角色权责」短句，信息给足；口播每页讲一件事，数字只放页脚，台上不念口径。

## 一、全场一句话

**所有的 AI 都在等人提问。化言让企业自己知道下一步该做什么。**

全场只重复两句话，其余不喊口号：

- **觉是组织的注意力，契是组织的记忆。**
- **研发向前一步，整个组织跟着向前一步。**

## 二、三项架构创新，各用一句话讲清

| | 今天的 AI 和 Agent | 化言架构机制 | 落到传化业务 |
|---|---|---|---|
| **觉** | **被动响应**：大模型等人提问，Agent 等人给目标，流程等上一步结束；漏问与跨单关联全靠人盯 | **组织的潜意识层**：持续接收业务变化，形成、维持、筛选候选事项，只把值得处理的提交给大模型、Agent 和人；按「决策家族 × 判断层」训练的本地模型 Jue-K 打分，发现环节零大模型调用；每次人工处置都回流训练 | 客户漏报的工况当场补齐；跨客户同类报障自动聚合成课题；历史搁置客户在新能力生效时自动触发回访 |
| **契** | **能读不等于能用**：文档进了知识库，判断仍锁在专家脑中；检索结果无边界、无人担责，要么泄密，要么只能再找专家 | **能读与能用分开**：依据、结论、能力三个对象；研发确认结论，再按岗位、条件、形式授予能力；能力以完整情境生效，超工况交回研发，源报告变化自动停用待审 | 研发签字确认一次，同工况需求一线直接调用；核心配方锁在研发层，对外只输出获准的型号、用法和说法 |
| **Harness** | **单点提效**：各岗位配独立助手，跨部门流转仍靠人工复制转述，信息逐级失真 | **单对象全链路协同**：从客户开口到研发结论、再到老客回访，全程挂在同一业务对象上；觉发掘事项、Agent 备料、人签字担责、契供给能力 | 一单到底，免去三岗来回转述；研发一项新能力生效，客户回访与产品说明书修订同步触发 |

**两者怎么咬合**：契决定组织此刻能用什么，觉在这些能力范围里学何时值得关注。前台反复碰到一项还没授予的研发判断，觉就向研发提出「要不要授予」；研发授予后，前台下一次就能直接用。

### P02 · 每个岗位都有了 AI，企业却没有变聪明 · 25 秒

**上屏**

- 标题：每个岗位都有了 AI，企业却没有变聪明
- 三格业务断层：
  - **缺工况无人追问**：客户只报「染花了」，面料、机型、温度缺失，单子照常往后传
  - **同类问题无人归并**：三位客户在不同时间问同一缺陷，散在各自会话里无人察觉
  - **历史结论无法复用**：研发三个月前已验证过的工况，新客户来问，还得再找研发重答
- 底部一线原话：「没有时间与精力去做中长期项目的探索」（传化一线研发）

**画面**：三格用真实界面的局部做底，比如一段只有现象的客户原话、两张互不关联的需求单、一份旧报告。每格右下角一个灰色问号。最下面放一线原话，字号小一档。

**台上讲**
> 今天，销售有了助手，研发能查资料，可组织还是原来的组织。客户没说清的条件，没人想到去问；三个客户在问同一件事，没人发现；研发三个月前答过的问题，新客户来问，还得再找研发。每个人快了一点，企业本身没有变聪明。

素材：M01、M05

### P03 · 给组织装上注意力、记忆和神经 · 25 秒

**上屏**

- 标题：给组织装上注意力、记忆和神经
- 三张卡，左边一行是上一页的问题（深红小字），右边一行是谁来管：
  - 没人追问，没人发现是同一个问题 → **觉**：它自己盯着，该问就问，该合并就合并
  - 研发答过的，还得再答一遍 → **契**：研发答一次，它记住，下一单直接用
  - 事情在岗位之间掉地上 → **Harness**：每件事都挂在同一张单上，有人接着办
- 底栏「带来什么」：以前要靠人想起来、记得住、跑去催的事，现在系统自己做。研发只管判断，**不用再补问和重答**。

**画面**：中间是组织架构底图，觉、契、Harness 各用固定颜色，后面每页沿用。三张卡左半边是深红的问题，右半边是机制色的解决办法，中间一个箭头。

**台上讲**
> 上一页那三件没人管的事，我们这样解决。该问的没人问，同样的问题没人发现，交给觉，它自己会盯。研发答过的还得再答，交给契，研发答一次它就记住。事情在岗位之间掉地上，交给 Harness，每件事都有人接着办。以前靠人想起来、记得住、跑去催的事，现在系统自己做。

### P05 · 觉：是什么让思考开始 · 45 秒

**上屏**

- 标题：大模型让机器会想，Agent 让机器会做，觉决定该想什么
- 左栏 · 今天的智能体：
  - 大模型：被问到才回答
  - Agent：被给目标才规划
  - 流程引擎：上一步结束才触发下一步
  - 共同前提：**得有人先把问题交给它**
- 右栏 · 觉：组织的潜意识层
  - **形成**：业务变化让一件事进入候选，例如条件不够判断、几份需求可能是同一个机会
  - **维持**：候选保留与原业务的联系，等客户、等试样、等专家是不同的等待
  - **筛选**：大多数候选留在后台、继续变化或自然消退
  - **提交**：只有值得处理的，才交给大模型、Agent 和人
  - **回看**：人怎么处理、结果如何，改变下一次的反射
- 底部类比：同一场冲突，普通人想躲开，受过训练的警察已经注意到危险来源和谁会被波及。**反射是基础，经验改变反射。**

**画面**：左右对比。左边三个图标（对话框、Agent、流程图）前面都站着一个「提问的人」。右边是觉的五段循环，底部从「回看」画一根反馈线回到「形成」。类比放最下面，用两个人的剪影。

**台上讲**
> 大模型让机器会想，Agent 让机器会做，但它们有一个共同前提：得有人先把问题交给它。现实里，值得解决的问题很少自己排好队。人不一样。普通人和警察看到同一场冲突，还没开始分析，警察已经注意到危险从哪来、谁会被波及。这是训练出来的直觉。觉给组织做的就是这一层：一直接收客户、产品、研发的变化，在后台形成、保留、筛掉大量可能，只把值得处理的事交给大模型、Agent 和人。人怎么处理，又会改变它下一次注意什么。

素材：M00、M03

### P06 · 觉：这层直觉是训练出来的 · 40 秒

**上屏**

- 标题：这层直觉不是提示词，是训练出来的模型
- 一张真实决策卡（产品机会）：
  - 看谁：一个需求主题
  - 什么时候才评估：同类需求升级 ≥ 2 次，且没有在途立项
  - 打分：不同客户数、升级次数、现有产品覆盖不足的程度
  - 交给谁准备：产品经理 Agent；谁签字：产品经理
  - 多急：涉及客户越多越急
- 模型做的事：对每一组「决策卡 × 业务对象」算出**此刻值得打扰人的概率和紧迫度**；大多数时候正确答案是「现在不提」
- 训练时改过的一件事：只奖励「追问后候选变了」，模型学到的是表面变化；改成「推荐有没有由错变对」「研发必问的条件有没有补齐」，它才开始替下游着想
- 上线门槛：每类决策单独比，统计上赢过规则才启用；知识冲突这一类规则已经够好，就留给规则
- 证据条：
  - 化言 Jue-K（校准后 AUC，对比规则）：客户追问 0.755 / 0.670 · 研发回问 0.713 / 0.500 · 产品机会 0.953 / 0.854 · 泄密风险 0.941 / 0.500
  - JUE 物流 jue_v0 R2：约 459.6 万个决策评估单元训练；同等打扰预算下新问题召回比强规则高 0.177；对照大模型发现原型，发现环节大模型调用 6,506 次 → 0 次
- 页脚：功能化学已有 27 类业务决策 · Jue-K 训练样本 15,399 条；均为模拟数据上的训练与评估

**画面**：左半屏是决策卡，做成真实配置的可读版本（不放 YAML 原文）。右上是一条线：业务变化 → 觉评分 → 过门槛 → 派单 → 人处置 → 回流训练。右下两组证据条，化言一组、物流一组，标注「两个领域，同一套架构」。

**台上讲**
> 这层直觉不是一段提示词，是训练出来的模型。每一类该不该做的事是一张决策卡：看哪个对象、什么前提下才评估、交给谁、谁签字。模型对每张卡算的是：此刻值不值得打扰人。我们训练时踩过一个坑：只奖励追问后结果变了，它就学会了制造表面变化；改成看推荐有没有由错变对、研发要的条件有没有补齐，它才开始替后面的人着想。这套方法在物流和化工两个领域各训练出一套模型，物流那套把发现环节的六千多次大模型调用降到了零。

素材：M03

### P07 · 客户还在线，该问的工况已经问清了 · 40 秒

**上屏**

- 标题：客户还在线，该问的工况已经问清了
- 初始报障：「深一块浅一块。」（缺面料、缺机型、缺温度）
- 觉实时追问：什么面料成分？什么染色设备？溢流缸还是气流缸？保温多少度？
- 当场补齐工况：`纯涤` · `气流染色机` · `135℃`
- 研发接收视图：客户原话 + 结构化工况卡 + 产品经理 Agent 整理的产品需求单
- 核心对照指标：
  - **进研发时关键工况完整率**：49.2% → **90.9%**
  - **进研发后因缺信息退回补问率**：95.1% → **19.5%**
- 页脚：模拟对照，300 张模拟需求卡中应进研发的 41 张；对照组为业务员人工转述，化言组为 Jue-K 实时追问

**画面**：左边三轮对话，中间条件卡逐项点亮，右边研发需求单局部，原话入口高亮。两个数字放在右下，用原生图表。

**台上讲**
> 客户说深一块浅一块。觉马上判断：面料和设备不问清，后面谁都没法判断。客户补了纯涤、气流缸、135 度，产品经理 Agent 把它整理成产品需求，研发拿到的是原话加完整工况。同一批模拟需求的对照里，进研发时关键信息齐全的，从不到一半到了九成；进了研发还得退回去补问的，从九成五降到两成。

### P08 · 两位客户互不认识，企业看见了同一个机会 · 30 秒

**上屏**

- 标题：两位客户互不认识，企业看见了同一个机会
- 散落需求输入：客户甲、客户乙在不同会话提交同类气流缸匀染痛点与工况
- 觉主动归并：跨会话识别共性工况诉求，生成「产品机会卡」推送产品经理
- 产品经理工作面：并排调阅两位客户原话、工况参数对比表及历史同类反馈
- 立项直通研发：产品经理确认立项 → 两条零散咨询合并为一项研发攻关课题
- 小字：同一客户反复问同一件事不算机会，这是觉专门要学会「不提」的困难样本

**画面**：先只出两个客户的原话，停半秒。两张卡之间亮起同一个主题，产品经理工作面弹出一张真实的机会卡，关联两位客户。最后点亮「产品判断 → 研发课题」。

**台上讲**
> 这是两位互不认识的客户，各说各的问题。没有人把他们联系起来，觉看见了：这是同一类需求。产品经理收到的不是两条零散消息，是一张带着两位客户原话和工况的产品机会卡。他判断值得做，研发就接到一项合并后的课题。市场上散落的声音，自己找到了产品经理。

素材：M03、M04

### P09 · 契：能读和能用，是两件事 · 40 秒

**上屏**

- 标题：读懂知识，不等于组织会用知识
- 左栏 · 今天的两难：
  - 研发报告进了知识库，销售仍不知道能不能对客户说
  - AI 读懂了报告，也没有权利替研发做产品承诺
  - 全部开放就泄密，全部锁死就只能再找专家
- 中栏 · 契的三个对象：
  - **依据**：报告段落、试验记录、公开说明，留在原系统，契只存能回到原文的指针和指纹
  - **结论**：研发依据这些材料确认的判断，带确认人和密级。回答「我们确认了什么」
  - **能力**：结论进入业务的接口，写明给谁用、什么条件下用、以什么形式用。回答「我们允许组织怎样用」
- 右栏 · 六种能力形式：说法（客户口语对上专业条件）· 追问 · 适用 · 转译 · 可说的话 · 定向说明
- 底部例子：同一份 L3 研发结论，可以只授给客户入口一项「该问染浴 pH」的追问能力，客户侧看不到报告一个字
- 底部类比：病人不读药理论文，也能按医嘱用药

**画面**：中间三个对象一字排开，依据 → 结论 → 能力，两道箭头上分别写「研发确认」「授予」。右栏六个小图标。底部例子做成一条从 L3 结论到 L0 客户入口的细线，线上只走「追问 pH」，报告本身留在 L3 框里。

**台上讲**

### P10 · 契：一项判断，只在它被验证过的情境里成立 · 40 秒

**上屏**

- 标题：一项判断，只在它被验证过的情境里成立
- 不许拼凑：一款助剂在「锦氨 × 气流缸」验证过，在「纯锦 × 溢流缸」也验证过，**不能**推出「锦氨 × 溢流缸」也行。契把每个结论当成一整组条件用，不拆开交叉组合
- 三种匹配结果：
  - 条件全部落在已确认范围内：**确认适用**，直接推荐
  - 条件还没问全：**可能适用**，觉回去问
  - 条件超出范围：**未覆盖**，交研发
  - 没读清、表达不了的限制原文保留，交研发处理，**未知不当成不限**
- 向上找，向下还：内部可以跨层找到相关的研发依据，返回给前台的只能是已授予前台的能力；没有授予，客户侧连「这里有一条被挡住的知识」都看不到
- 三道签字，各管一件事：
  - **确认**：研发判断结论成立，签的是他当时看过的那一版证据
  - **授予**：由确认人决定给谁、在什么条件下、以什么形式用
  - **批准**：涉及产品适用范围，产品经理签
- 能力会停：源报告一改，指纹对不上，相关能力自动挂起，等研发复核
- 能力有主：每被调用一次，记在确认人名下；统计的是「被使用」，不是「被检索」

**画面**：上半屏左边是不许拼凑的二乘二格子，四格里两格打勾、一格打叉、一格问号。右边三种匹配结果三条路。下半屏是一条能力的生命线：候选 → 确认 → 授予 → 批准 → 在用 → 挂起 → 复核，签字点标人名。

**台上讲**
> 技术判断最怕的不是编造，是把局部成立的结论悄悄放大。一款助剂在锦氨配气流缸上验证过，在纯锦配溢流缸上也验证过，不代表锦氨配溢流缸也行。契把每个结论当成一整组条件来用，不拆开拼。条件齐了，确定推荐；没问全，先回去问；超出范围，交给研发。研发签字时，签的是他看过的那一版报告，报告一改，能力自动停下。它每被用一次，都记在确认人的名下。

**全场最后一句**
> 前一单留下的判断，已经改变了这位客户今天得到的服务。我们想把这件事，做成传化每个事业部都能用的能力。

## 七、制作要求

全篇以队友做好的 P02「每个岗位都有了 AI，企业却没有变聪明」为母版。下面的颜色值是从 P02 截图估出来的，以队友源文件里的实际取值为准。

### 7.1 每页固定的五个区域

| 区域 | 做法（照 P02） |
|---|---|
| 页眉 | 深海军蓝渐变通栏。左上「化言 HUAYAN」标识；右上「页码 / 19 · 段落名 · 本页关键词」，例如「05 / 19 觉 · 认知入口」；下方白色大标题，标题就是本页主张 |
| 正文 | 浅蓝白底。内容放进白色圆角卡片，卡片细蓝描边；卡片左上用「01 客户询单」这种蓝色序号小标题 |
| 流程 | 卡片之间用细蓝箭头连。退回、断层、拦截这类「出问题」的路径用深红弧线加深红胶囊标签，例如 P02 的「原路退回：关键工况仍未问清」 |
| 底栏 | 深海军蓝通栏。左边小标签，右边一到两句本页结论，关键词用粉红高亮。结论只回答两种问题之一：**为什么需要**（如 P02「业务代价」），或**这样做带来什么**（如 P03「解决什么」）。不复述标题，不预告后面的页。每页都有，评委只看底栏也能串起全场 |
| 页脚 | 一行小字。左边写数据或图片来源，例如「基于传化一线反馈的场景复原 · 织物为示意图」；右边写「化言路演 / 段落名」 |

| 主蓝 | `#1D5FA8` | 序号小标题、普通流程箭头、Harness |

## 八、备答清单（不进主讲）

1. 觉、Jev、角色 Agent 各管什么，谁能调用谁：觉提出问题，Jev 回答已经提出的问题，Agent 准备，人签字。
2. 觉为什么不直接用大模型轮询：成本、稳定性、审计；发现分高不等于有权行动，发现、发布、处理、授权四层可以分开评估。
3. Jue-K 怎么训练：72 维特征，按「决策家族 × 判断层」训练梯度提升树并做 isotonic 校准；每类配对 bootstrap，AUC 置信下界大于 0、Brier 上界小于 0 才启用，否则退回规则。
4. Jue-K 的标签怎么改过：从「候选集合变化」改到「推荐由错变对」，再加入「应进研发的需求是否补齐必问条件」；未见现象上的追问泛化还不稳定。
5. JUE 物流 jue_v0 R2：484 个特征、约 459.6 万个评估单元；同分布新环境 R_new 0.647、未见拓扑 0.679；R_signal 0.763 未到预设 0.80，客户挽留类偏弱。
6. 41 张需求卡的完整对照：业务员转述、一次性翻译、规则觉、Jue-K 四组；全部 300 张卡上规则觉反而更好的原因（Jue-K 把追问预算投给更可能进研发的需求）。
7. 觉的能力阶梯 L0—L4：今天在 L0 特化决策发现；经验可塑、开放候选、自发探索、跨场景通用各需要什么证据。
8. 契的六种能力形式和同层共享分别怎么生效；授予人必须是结论确认人；确认、授予、产品范围批准、撤销、同层归属分别由谁做。
9. 契和 RAG 的分工：RAG 提供依据，模型理解和起草，专家确认与授予，契让授权进入系统行为；企业原有知识库可以继续当依据来源。
10. 6→2、4→8 的契复用对照（14 题脚本），研发处置由脚本设定。
11. 109 份报告编译的细节：Evidence Block、知识中间表示、条件是知识的一部分；哪些交了人工，错误别名案例；表格读数核对例子（TF-1871 第 15 页原表，两个数值和单位都对上）。
