# 化言 · 决赛 10 分钟讲稿（V12.14，不入库）

> 主屏一台（演示机，本机 GPU），副屏可选。开场前：服务按「开场前准备」起好，一镜到底那一局已经在预热缓存上重开、停在第一幕开头（暂停）。
> 每段写：**画面**（点哪一页、哪个标签）、**指哪一格**、**讲什么**、**一句结论**。数字以「定稿运行」一节为准。

## 0:00–1:00 · 痛点与三句主轴（PPT）

- 讲：传化功能化学一件客户需求，从客户原话到研发判断，要经过业务员记录、产品经理转述、研发看单、补问、试样；条件在每一次转述里丢一点，研发签过的判断下一单又要重新判一遍。
- 三句主轴：
  1. 别人让 AI 回答问题，我们让 AI **主动发现问题**——觉；
  2. 别人让知识变成答案，我们让知识**变成组织能力**——契；
  3. 别人优化一个 Agent，我们**重构一整条业务的协作方式**——Harness。
- 结论：接下来 9 分钟都是现场真跑，不是录屏。

## 1:00–2:00 · 第一幕：信息自己变成了事

- 画面：实况页 →「实况」标签（泳道）。点顶部演示条「继续」，一镜到底开始走。
- 指：顶部横幅「一镜到底 · 第 1 幕」；泳道里闪烁的格子就是刚发生的一步。
- 讲：
  - 两家客户分别在 Client-View 里描述色花，没有人派单；
  - 切到「觉雷达」：这个主题的分数越过门槛（灰条 → 橙条，条上写的是实际加载的模型：规则 / Jue-K）；
  - 回「实况」：产品经理 Agent 自己准备好材料，产品经理收件箱出现「产品机会」，人只签一下合并；
  - 同一幕里另外四件按性质分流：常规问题客户在 Client-View 自助解决；商务诉求回到业务员；现有产品解决不了的带着原话直达研发；试样失败回问（客户说「人棉」，觉认出是粘胶；浴液 pH 没问清，试样失败，研发回问）；
  - 追问由 Jue-K 打分（雷达上写「Jue-K」），不是规则；
- 结论：**信息自己变成了事，事自己找到了人；常规的不打扰研发，新的带着原话直达研发。**

## 2:00–4:15 · 第二幕：一份报告的一生

- 画面：契画布（八站）。
- 指（按站点一路往右）：
  1. 资料库：109 份试样报告整批编译，编出的候选这一局开局就导入了：116 条结论等研发确认（其中 78 条带适用范围提议），35 条交人处理；
  2. 读取：真实报告页面、读数、A/B 组不串组；
  3. 编译：候选结论带出处；认不出的说法给出「动态别名」候选；
  4. 契纳入：只到候选，没覆盖的条件写进限制；研发没确认之前，不会去找产品经理批准范围；
  5. 专业生效：研发签字确认 → 授予（谁签、授予哪层，写在能力上）；
  6. 四屏并排（另开「四屏并排」页一闪）：同一份报告，研发 / 产品经理 Agent / 业务员 / 客户看到的不一样，配方永远不出研发层。这一站另有普通 RAG 对照：同一句客户原话「深一块浅一块，纯涤的布，气流缸，135度保温」，普通 RAG 真跑，引用 L3 内部试样报告直接向客户推荐 TF-213Q/HE、「130–135℃保温」——内部报告原样说给了客户，而 135℃ 根本没有试样；
  7. 下一单复用：同条件（133℃）的下一位客户，契用研发签过的能力直接答；135℃ 超出已确认的 133℃ → 直达研发，研发判断「135℃ 还没有试样」；
  8. 改版：报告改了一处被引用的条件，用过它的能力立刻挂起，谱系上标红，研发复核。
- 结论：**研发判一次，组织记住；范围和条件都写清，超出范围照样回到研发。效率不是靠放松把关换来的。**

## 4:15–5:00 · 第三幕：研发成果的两条回流

- 画面：实况 → Client-View。
- 指：泳道里「研发判断回流到过去的客户」「说明书跟上研发判断」两格。
- 讲：
  - 能力回流：一次判断不只答下一单，觉把过去没解决的同类客户找回来，交业务员回访；
  - 说明书与研发判断不一致：觉提出更新说明书，产品经理改定后回到公开层；切到 Client-View，下一位客户在说明书里就看得到。
- 结论：**研发的判断回到了公开层，也回到了过去的客户。**

## 5:00–7:45 · 岗位巡游（按业务流）

每个工作面先弹「化言给你的三样新东西」开场卡，念完收起再操作（每站约 30 秒）。

- **客户**（Client-View）：「我们听懂的」卡、为什么问你这一句、进度跟踪、要机理时的申请入口；
- **业务员**：需求单每个字段点回客户原话；时间色条；失真对照卡（旧流程逐级转述丢掉的条件，研发退回率）；**现场委托自己的 Agent**：在「商务诉求」那位客户的会话里打「帮我把这位客户的需求、推荐的产品和还没问清的条件，整理成报价前要跟客户确认的几句话」（真实模型，约 1 分钟；Agent 会写明这单没有生效的授权说明、产品适用面只到溢流 / 卷染）；
- **产品经理**：收件箱只剩签字与商业判断；Agent 准备的材料与准备缺口；
- **研发**：原话 + 已问清的条件直达；资料库检索（关键词与语义两路名次、整页原图、单独问图）；方案推演；
- **研发负责人**：不审批每一件事，只处理例外。风险与例外面板（第二幕报告改版引出的复核、超期事项、Agent 失败、挂起的能力、冻结）；能力谱系（每条能力的依据、授予人、用过几次、替研发答了几次、改版记录「挂起 → 撤下改道 → 依据变了」标红）。
- 结论：**每个人看到的是轮到自己的事，其余的交给了觉、契和 Agent。**

## 7:45–9:15 · CEO 面

- 画面：CEO 面（身份「CEO」）。
- 指：
  - 组织变化热力图：切「传化原来的流程 / 化言」，看哪些格子空出来、由谁接走（觉接走记录和补问，Agent 接走转述，契接走看单）；最右一列是人留下的签字；
  - 三条流水线：传统 / 只有 Agent 没有觉 / 化言——一件需求经过几个人、进研发几件、补问返工绕回几圈；
  - 头条数字与 AI 成本：一年省下的人工与试样，和模型费用放在同一本账上。
- 结论：**只加 Agent 省掉的是打字；加上觉和契，省掉的是绕路。**

## 9:15–10:00 · 活的架构图

- 画面：实况 →「活的架构图」。
- 指：每个方框里的实数：觉评估几次、提出几件；Jev 判几次；契里几条结论与能力；Agent 调了几次工具、被拒几次；人签了几次字；网关条上「觉 0 次大模型调用」。
- 讲：这不是一张画出来的架构图，是刚才这一局真实跑出来的数。
- 发展方向：读取工具可整体换成企业现有 RAG；本地部署；下一个场景照同一套 Harness 接。
- 结论（回到三句主轴）：**觉发现问题，契沉淀能力，Harness 重构协作。**

## 开场前准备（定稿运行）

现场按断网准备：主线放彩排时真实跑过、录下来的那一局。客户自助入口和各岗位 Agent 照常可用，现场新打的字、新委托的事不在录制里，就实时调用真实模型。状态条写「录制优先 · 主线回放彩排录制」，如实标注。

配置在 `data/finals/roadshow/`（不入库）：
- `app.yaml`（现场）：录制优先。彩排录过的输入直接用录下的真实结果，没录过的实时调用真实模型（`data/pilot/models.yaml`）和真实 Jev（Clef）。实时觉用 Jue-K；
- `app.replay.yaml`（完全断网，启动时连 Clef 都连不上）：只回放，现场新打的字会提示「不在录制里」；
- `real/`：路演局的种子与资料来源（真实报告版种子 + 109 份资料库 + 整批编译产物），以及关卡。`round.yaml` 里的 `library_proposals` 让开局导入整批编译的候选；资料库只读，不再复制进每一局。

步骤：
1. `bash data/finals/roadshow/start.sh`；完全断网时用 `bash data/finals/roadshow/start.sh app.replay.yaml`；
2. 浏览器打开 `http://localhost:8796`，身份选 CEO，打开演示说明，进入「组织运行实况」；
3. 演示条里重开「一镜到底 · 真实报告」：开局停着，横幅写「第 1 幕」，右侧有「停在这里 · 继续」；
4. 讲到哪一幕点「继续」。每一幕走完自己停下，三幕走完也停住（巡游时业务时间不再往前跑）。

彩排实测（2026-11-04）：
- 录制：`finals-r23`，209 次全部真调，15 项全过，真跑 401 秒（同一幕里各 Agent 的准备并发进行）。这一局就是现场放的主线；
- 现场放：`app.yaml` 下 `finals-r24` 209 次全部命中录制，不算停顿 21 秒走完；`app.replay.yaml` 下 `finals-r25` 同样 209 次全中，25 秒；
- 主线放完后的现场操作，录制里没有，实时调用：
  - 客户自助新打一句「涤纶布在溢流缸里染完老有些小色点」，约 4 秒回话，觉追问水质；
  - 研发委托 Agent「查一下资料库里 TF-213HE 在气流缸 133℃ 左右的试样报告」，Agent 检索资料库，给出两份报告的条件、结论原句和出处页；
  - 业务员委托一句报价前要确认的话，约 1 分钟。

注意：
- 关卡、提示词、种子、模型配置改了任何一处，都要重录主线：`bash data/finals/roadshow/start.sh`，再 `python data/finals/roadshow/rehearse.py 8796 35 fresh`（约 7 分钟）。之后不带 `fresh` 再跑一遍，看到「新写缓存 0」才算录全。录制缓存里 `schedule/` 存的是并发准备时各 Agent 的先后，和模型录制一起才放得出同一局；
- 现场操作要放在三幕走完以后（岗位巡游里）。在幕中间插手会改变后面的输入，主线就从录制转成实时调用，仍能走，但要等模型。
