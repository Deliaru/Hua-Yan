# 化言：让专业能力成为企业持续创新的力量

## 一、化言要改变什么

一家企业可以拥有优秀的专家、成熟的产品和丰富的知识，却仍然没有足够的精力开发下一代产品。客户的需要经过反复转述才到达研发；专业人员一边做判断，一边补问信息、解释术语、追踪进展；相似问题再次出现，同一批人又被叫回来。专业能力没有消失，却被重复沟通和零碎工作不断占用。

化言从功能化学的需求协作进入这个问题。我们希望让客户的真实需要更早被理解，让已有专业成果直接参与业务，让新的问题准确进入值得投入的专业工作。由此释放的，是销售经营市场、产品经理经营产品、研发创造新能力的时间与精力。

**化言的产品愿景是企业决策神经系统：持续感知业务变化，发现值得处理的问题，组织合适的专业能力，并把处理经验留给下一次业务。**企业每解决一类问题，都应增加一份能够继续服务客户的能力；企业每天面对的信息，也应成为理解市场、形成产品方向和开展长期研发的来源。

这个愿景从需求入口生长。需求连接市场与企业，需求质量影响后续判断和开发，专业成果最终也要回到客户的使用之中。把这条关系做深，就能触及企业如何使用专业人才、积累能力和创造未来。[1]

## 二、价值落在岗位的工作变化上

研发反馈给出了明确的因果链：需求沟通不畅造成反复交叉对接；需求不明确造成开发偏差和返工；短平快项目持续消耗精力，中长期探索因此被挤压。化言应沿着这条链解决问题，让每个岗位在需要其专业价值的地方参与。[1]

| 岗位 | 希望由系统承担的重复工作 | 人更集中投入的专业工作 |
| --- | --- | --- |
| 销售 | 技术信息收集、重复转述、按已有知识补问、追踪技术事项 | 客户关系、产品销售、商务推进、现场协调与客户反馈 |
| 产品经理 | 逐单解释客户场景、重复准备产品需求、整理已有转化依据 | 产品适用范围、产品机会、全生命周期管理、例外判断与转化经验沉淀 |
| 研发 | 猜测不完整需求、反复补问、重复回答同类问题、因理解偏差返工 | 新技术问题、必要定制与技术支持、实验验证、中长期产品开发 |

客户—研发直达，意味着客户的原始目标、条件与约束能够准确进入专业判断。常规问题可以先由已有能力解决，商务事项进入销售工作，产品事项进入产品经理判断，确需研发的问题带着充分上下文到达研发。缩短传递链与提高需求质量共同成立，岗位才可能真正回归。

由此形成三层价值：客户更容易获得专业服务；专业人员的一次投入能够服务更多业务；企业有条件持续配置精力给新产品和长期课题。近期试用观察前两层的具体变化，长期发展继续检验它们怎样转化为创新投入与经营成果。文档中的价值主张沿这条因果关系展开。

## 三、觉：让信息成为值得思考的事情

智能系统通常擅长回答已经提出的问题。但在真实组织里，信息先到来，问题未必已经被说清。客户补充了一项条件，几次试样暴露了相似缺口，旧判断遇到了新的适用场景；这些变化是否值得关注，什么时候值得深入思考，需要谁参与，本身就是智能工作的一部分。

**觉研究“什么值得开始思考”。**它关注任务产生之前的过程，并持续跟进已经出现却尚未解决的事项。完整的思想包括四个相连的环节：从信息和变化中形成候选事项；维持事项的状态与上下文；根据目标、紧迫性和处理价值筛选注意对象；把值得判断的事情提交给高层模型、专业 Agent 或人。后续处置又成为下一轮关注的经验。[1][2]

这层分工使持续关注与深入推理能够各自发挥作用。觉保持对业务的注意，高层模型组织推理，Agent 准备材料并执行允许的动作，人承担专业判断与责任。一个问题被提出以后，系统还需要知道它有没有解决、条件是否改变、是否值得再次关注，避免每次都从零开始，也避免对同一件事反复打扰。

“潜意识反射”提供了理解这项研究的直观类比。普通人和受过训练的专业人员面对同一场景，会迅速注意到不同的线索。经验改变了他们认为重要的事情。对应到智能系统，预设机制提供基础反应，处置经验塑造后续注意：哪些信号值得提前追问，哪些组合值得联系起来，哪些提醒没有处理价值，哪些已经解决的事项应当安静下来。

明确的业务事实可以由规则承接，经验模式可以交给可训练的机制，复杂推理交给高层智能。觉的研究价值在于把信息反射、状态维持、注意选择与经验学习组织成持续工作的能力。功能化学中的追问、回问、机会和冲突，为这项思想提供了可以观察、比较和改进的具体场景。

随着研究推进，我们希望觉能理解更开放的信息关联，形成更丰富的待处理事项，并在有限的计算与人的注意力之间作出更好的分配。当前实现与已取得的实验结果见 [STATUS](STATUS.md)；这一节说明完整研究方向。

## 四、契：让一次专业工作持续供给能力

专家完成判断后，如果后续每一次使用都必须重新找到本人，专业服务的规模仍受限于专家的时间。化言希望让经过确认的专业成果进入组织的日常工作：研发确定的适用结论、产品经理形成的需求转化经验，都能够在后续业务中发挥作用。

**契组织的是专业能力的供给。**判断有来源、有贡献者、有适用条件；有权的人决定它可以支持谁、在哪些范围内做什么。业务人员能够使用所需的专业能力，专家保留对判断的确认、授予与修订权。读到全部知识与获得某种使用能力可以分别安排，专业能力因此能够跨岗位流动。[1][3]

研发确认一个产品在某类工况下适用，可以改变后续客户的选型与处理；产品经理确认一种场景描述怎样转成产品要求，可以减少下一单的转述与解释。两类贡献同样重要。客户需要怎样进入产品语言，产品能力怎样对应市场场景，本来就包含产品经理的专业经验。

条件、来源和修订机制支撑能力持续发挥价值。新情况出现时，系统应识别哪些既有判断仍然适用，哪些部分需要重新交给专业人员。人的贡献也应被看见：谁形成了判断、谁确认了产品边界、哪份经验正在被后续业务使用，应能回到相应贡献者。

契的价值应在前后两次业务中显现：第一次需要专业人员解决的问题，第二次已经有能力可以调用；条件发生变化时，需要重新判断的部分又能准确出现。这样的积累使个人经验逐步成为组织能够持续供给的专业服务。

## 五、语义编译与按需协作，把思想接入业务

客户描述的是使用情境、现象和期待，产品经理需要判断产品要求，研发需要理解技术条件。语义编译承担这些语言之间的转换，并保留原始目标、条件与依据。客户修正了设备、材料或约束，后续准备和判断也应承接这次变化。只有含义在传递中持续成立，专业工作才会从正确的问题出发。[1][2]

觉、契与 Agent 因此形成一条有业务意义的关系：业务变化带来值得处理的事项，已有专业能力先参与解决，Agent 准备必要材料，合适的岗位作出判断，成果再进入后续业务。知识分层界定信息的使用边界，协作路径则根据问题的性质展开。

例如，一位客户的条件不足，系统先追问；需求清楚后，已有能力可能直接提供服务，也可能显露新的专业缺口。产品经理判断产品范围或共性需要，研发处理技术问题。经确认的结果留下新的能力，相关人员据此推进客户工作。下一次相近需求到来，组织已经拥有不同于上一次的处理基础。

化言对企业的改变，可以通过这条关系看见：信息进入组织后能否形成有价值的工作，人的判断能否改变后续处理，专业投入能否逐渐积累。功能数量只是这些变化的承载方式。

## 六、两条相互支撑的长期路线

### 产品路线：从需求协作走向企业决策神经系统

起点是功能化学需求链，重点是客户语言、专业判断与真实工作之间的连接。随着业务积累，化言可以进一步连接更多产品线、研发任务、生产和应用场景，让分散的专业成果更容易被需要它的人使用，让共性问题更早进入产品与研发视野。

继续向产业延伸，上游技术语言、企业产品语言与下游使用语言之间存在大量理解成本。化言希望成为这些语言与专业能力之间的连接：把使用问题准确带给能解决它的专业主体，把经过验证的能力送回适合它的业务场景。产品适用边界、贡献归属和结果反馈随这条连接共同延伸。

这条路线的长期价值，是使专业型企业更充分地使用既有成果，更持续地发现新问题，更有余力开发未来产品。企业决策神经系统描述的是这种持续感知、判断、协作与积累的能力。

### 技术路线：从业务信息流走向通用信息反射

觉的研究问题不限于企业业务。持续接收变化的 Agent，同样需要形成和维持任务，判断何时值得调用更昂贵的推理；机器人与具身智能需要在环境变化、注意、反射、规划与行动之间协调；更自主的智能系统需要围绕目标、记忆与经验持续发现值得处理的事情。

因此，通用信息反射是觉的技术远景。化言提供真实而复杂的组织场景，使这些问题可以从业务中的信息、判断与结果开始研究。远期探索围绕任务发现、注意形成和经验塑造展开，逐步检验可迁移的机制与需要重新学习的部分。

## 七、从当前工作走向这个愿景

V9 真人试用是让这套思想进入实际岗位的一步。试用应观察需求怎样被理解、谁在何处作出专业判断、哪些重复工作已经被系统承担、已有成果怎样被再次使用，以及觉在哪里帮助人更好地关注问题。它们既影响下一轮产品判断，也支撑路演中的企业价值论证。

后续开发围绕真实业务与核心主张选择。市场与研发成果的更广回流、多需求联系、反馈学习深化，都有进一步研究的价值；具体做到哪一步，应由业务收益和证据需求决定。当前讨论没有把需求池扩建、全景视图或某套 V10 功能确定为必做任务。
